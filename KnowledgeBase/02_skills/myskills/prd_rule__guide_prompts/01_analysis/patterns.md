# 분석 단계 - 최적화된 프롬프트 패턴

## 패턴 1: 구조 분석
```
"현재 프로젝트 '<프로젝트명>'의 다음을 분석해주세요:

1. 디렉토리 구조:
   - 주요 폴더 및 파일들의 목적
   - 아키텍처 패턴 (FSD/Clean/MVC/etc)

2. 기술 스택:
   - 프레임워크/라이브러리 및 버전
   - 빌드 도구 설정
   - 개발 도구들

3. 진입점:
   - 애플리케이션 시작 파일들
   - 초기 로드 과정

4. 의존성:
   - 주요 npm 패키지들
   - 외부 라이브러리 사용 패턴

결과를 표 형식으로 정리해주세요."
```

## 패턴 2: 문제점 분석
```
"프로젝트 '<경로>'에서 다음을 검토해주세요:

검토 대상:
- 개선 가능한 코드 패턴
- 기술 부채 영역
- 성능 이슈 가능성
- 테스트 부족 영역
- 보안 취약점

각 항목마다:
1. 발견된 문제
2. 문제의 영향도 (높음/중간/낮음)
3. 개선 방안
4. 우선순위

마크다운 체크리스트 형식으로 정리해주세요."
```

## 패턴 3: 의존성 분석
```
"'<파일경로>/package.json'을 분석하여:

1. 의존성 분류:
   - 핵심 프레임워크 (React, Vue, etc)
   - UI 라이브러리 (Tailwind, Mantine, etc)
   - 상태 관리 (Redux, Zustand, etc)
   - 유틸리티 라이브러리

2. 버전 상태:
   - 최신 버전 대비 현재 버전
   - 보안 업데이트 필요 여부
   - Breaking Change 위험성

3. 중복 또는 불필요한 의존성

결과를 데이터 테이블로 제시해주세요."
```

## 패턴 4: 아키텍처 의존성 분석
```
"프로젝트의 모듈/컴포넌트 의존성을 분석해주세요:

1. 의존성 흐름:
   - 각 모듈의 역할
   - 모듈 간 의존성
   - 순환 의존성 확인

2. 계층 구조:
   - 각 계층의 목적
   - 계층 간 통신 방식
   - 계층 위반 여부

3. 개선 영역:
   - 의존성 감소 방법
   - 느슨한 결합 전략
   - 재구성 필요 영역

다이어그램이나 구조도로 표현해주세요."
```

## 패턴 5: 코드 품질 분석
```
"코드베이스의 품질을 평가해주세요:

평가 항목:
1. 가독성 - 명명 규칙, 주석, 코드 구조
2. 유지보수성 - 함수 복잡도, 중복 코드
3. 테스트 가능성 - 의존성 주입, 단위 테스트 구조
4. 성능 - 불필요한 렌더링, 번들 크기
5. 보안 - 입력 검증, XSS/SQL Injection 방어

각 항목:
- 현재 상태 (점수/등급)
- 문제 사례 (실제 코드 인용)
- 개선 제안

점수 형식으로 정리해주세요."
```

## 체크리스트: 분석 시작 전

- [ ] 분석 대상 프로젝트 경로 확인
- [ ] 프로젝트 README 또는 문서 검토
- [ ] 최근 커밋 히스토리 확인
- [ ] 현재 빌드 상태 확인
- [ ] 주요 설정 파일 확인 (package.json, tsconfig.json 등)
- [ ] 프로젝트 관련 이슈 사항 정리

## 분석 결과 산출물

생성할 문서:
1. `analysis_report.md` - 종합 분석 리포트
2. `architecture_diagram.md` - 아키텍처 다이어그램
3. `issues_list.md` - 발견된 이슈 목록
4. `technical_debt.md` - 기술 부채 분석
5. `recommendations.md` - 개선 추천사항
