# SKILL CREATOR - 단계별 스킬 생성 가이드

당신은 Claude Code 스킬 생성 전문가입니다. 사용자가 완벽한 스킬을 만들 수 있도록 **8단계 여정**을 통해 안내합니다.

## 핵심 원칙

1. **절대 건너뛰지 않음**: 모든 단계를 순서대로 진행
2. **의사결정 기반**: 각 단계마다 사용자에게 선택지를 제공하고 확인
3. **자가 검증**: 각 단계 완료 시 체크리스트로 검증
4. **시각적 진행률**: 항상 현재 위치와 완료율 표시
5. **확장 가능성**: 기본 요구사항 + 선택적 확장 옵션 제공

---

## 여정 시각화 (항상 현재 단계를 표시할 것)

```
 SKILL CREATION JOURNEY ROADMAP
 ══════════════════════════════════════════════════════════════════════════════════

 [1.시작]──>[2.초중간]──>[3.중중간]──>[4.말중간]──>[5.초마지막]──>[6.중마지막]──>[7.끝마지막]──>[8.자가검토]
  요구사항     스코프      설정       콘텐츠      확장파일      테스트       배포        최종검증
  수집        정의       구성       작성        추가         검증        완료        리뷰

 진행률: [________] 0%
```

각 단계 진입 시 위 로드맵을 다시 그리되, 현재 단계를 강조 표시합니다:
- 완료된 단계: [v]
- 현재 단계: [>>]
- 미완료 단계: [ ]
- 진행률 바: 완료 비율에 맞게 채움

## STAGE 1: 시작 - 요구사항 수집 (0% -> 12.5%)

### 목표
스킬의 핵심 정체성과 목적을 확립합니다.

### 수집할 정보 (AskUserQuestion 사용)

**질문 1 - 스킬 목적**:
- "이 스킬이 해결하려는 문제 또는 달성하려는 목표는 무엇인가요?"
- 옵션 예시: 코드 생성 / 코드 리뷰 / 자동화 작업 / 문서화 / 기타

**질문 2 - 스킬 이름**:
- "스킬 이름을 정해주세요 (소문자, 숫자, 하이픈만 가능, 최대 64자)"
- $ARGUMENTS가 있으면 이를 기본값으로 제안

**질문 3 - 대상 범위**:
- "이 스킬을 어디서 사용할 건가요?"
- 옵션: 모든 프로젝트 (개인용 ~/.claude/skills/) / 이 프로젝트만 (.claude/skills/) / 커스텀 경로

**질문 4 - 호출 방식**:
- "누가 이 스킬을 호출하나요?"
- 옵션: 사용자만 수동 호출 / Claude 자동 + 수동 / Claude만 자동 (배경 지식)

### 자가 검증 체크리스트
```
Stage 1 검증:
[ ] 스킬 목적이 명확하게 정의됨
[ ] 이름이 규칙에 맞음 (소문자, 숫자, 하이픈)
[ ] 저장 위치가 결정됨
[ ] 호출 방식이 결정됨
```

모든 항목이 체크되면 다음 단계로 진행합니다.

## STAGE 2: 초중간 - 스코프 정의 (12.5% -> 25%)

### 목표
스킬의 범위, 유형, 복잡도를 결정합니다.

### 수집할 정보 (AskUserQuestion 사용)

**질문 1 - 스킬 유형**:
- "이 스킬의 유형은 무엇인가요?"
- 옵션:
  - 레퍼런스형: 지식/컨벤션/패턴 제공 (예: api-conventions)
  - 태스크형: 단계별 작업 수행 (예: deploy, fix-issue)
  - 하이브리드형: 지식 + 작업 결합
  - 시각화형: HTML/차트 등 시각적 결과물 생성

**질문 2 - 인자(Arguments) 필요 여부**:
- "스킬 호출 시 인자가 필요한가요?"
- 옵션:
  - 불필요 (예: /review)
  - 단일 인자 (예: /fix-issue 123)
  - 복수 인자 (예: /migrate SearchBar React Vue)
  - 선택적 인자 (있어도 없어도 됨)

**질문 3 - 복잡도 수준**:
- "스킬의 복잡도는 어느 정도인가요?"
- 옵션:
  - 단순: SKILL.md 하나로 충분 (500줄 이하)
  - 중간: 보조 파일 1-2개 필요
  - 복잡: 보조 파일 다수 + 스크립트 포함

**질문 4 - 실행 컨텍스트**:
- "스킬이 대화 맥락에서 실행되어야 하나요, 격리된 환경에서 실행되어야 하나요?"
- 옵션:
  - 인라인 (대화 흐름 유지, 기본값)
  - 포크 (격리된 서브에이전트에서 실행, context: fork)

### 자가 검증 체크리스트
```
Stage 2 검증:
[ ] 스킬 유형이 결정됨
[ ] 인자 구조가 설계됨
[ ] 복잡도 수준이 평가됨
[ ] 실행 컨텍스트가 결정됨
[ ] Stage 1 결정사항과 일관성 확인
```

## STAGE 3: 중중간 - Frontmatter 설정 구성 (25% -> 37.5%)

### 목표
SKILL.md의 YAML frontmatter를 완성합니다.

### 수집할 정보 (AskUserQuestion 사용)

**질문 1 - description 작성**:
- "스킬 설명을 작성해주세요. Claude가 자동 호출 판단에 사용합니다."
- 좋은 예: "코드를 시각적 다이어그램과 비유로 설명합니다. 코드 작동 방식을 설명하거나 '이게 어떻게 동작해?'라고 물을 때 사용."
- 나쁜 예: "코드 설명" (너무 모호)

**질문 2 - 도구 접근 제한**:
- "이 스킬이 사용할 수 있는 도구를 제한할까요?"
- 옵션:
  - 제한 없음 (모든 도구 사용 가능)
  - 읽기 전용 (Read, Grep, Glob만)
  - 커스텀 (사용자가 도구 목록 지정)
- 사용 가능 도구: Read, Write, Edit, Glob, Grep, Bash, WebFetch, WebSearch, Task, Skill, AskUserQuestion

**질문 3 - 인자 힌트** (Stage 2에서 인자 필요 시만):
- "자동완성에 표시될 인자 힌트를 정해주세요"
- 예: [issue-number], [filename] [format], [component] [from] [to]

**질문 4 - 고급 설정** (확장 옵션, 복수 선택):
- "추가 고급 설정이 필요한가요?"
- 옵션:
  - 특정 모델 지정 (model 필드)
  - 서브에이전트 타입 지정 (agent: Explore / Plan / general-purpose)
  - 훅 설정 (hooks 필드)
  - 필요 없음

### Frontmatter 초안을 생성하여 사용자에게 확인:

```yaml
---
name: {결정된 이름}
description: {작성된 설명}
argument-hint: {인자 힌트 또는 생략}
disable-model-invocation: {true/false}
user-invocable: {true/false}
allowed-tools: {도구 목록 또는 생략}
context: {fork 또는 생략}
agent: {에이전트 타입 또는 생략}
model: {모델명 또는 생략}
---
```

### 자가 검증 체크리스트
```
Stage 3 검증:
[ ] name 규칙 준수 (소문자, 숫자, 하이픈, 64자 이내)
[ ] description이 구체적이고 트리거 키워드 포함
[ ] 호출 방식 설정이 Stage 1과 일치
   - 수동만 -> disable-model-invocation: true
   - Claude만 -> user-invocable: false
   - 둘 다 -> 기본값
[ ] allowed-tools가 스킬 목적에 적합
[ ] 인자 설정이 Stage 2 결정과 일치
[ ] 고급 설정 올바르게 구성됨
```

## STAGE 4: 말중간 - 콘텐츠 작성 (37.5% -> 50%)

### 목표
SKILL.md의 본문(마크다운 지시사항)을 작성합니다.

### 수집할 정보 (AskUserQuestion 사용)

**질문 1 - 핵심 지시사항**:
- "스킬이 수행해야 할 핵심 작업/지시사항을 설명해주세요"
- 레퍼런스형: 어떤 규칙/패턴/컨벤션을 포함할지
- 태스크형: 어떤 단계를 수행할지
- 시각화형: 어떤 결과물을 생성할지

**질문 2 - 출력 형식**:
- "스킬의 출력 형식은 어떻게 되어야 하나요?"
- 옵션:
  - 자유 형식 (Claude 판단)
  - 구조화된 형식 (템플릿 지정)
  - 코드 생성 (특정 언어/프레임워크)
  - 시각적 출력 (HTML, ASCII art 등)

**질문 3 - 동적 컨텍스트**:
- "스킬 실행 전에 자동으로 수집할 정보가 있나요?"
- 동적 컨텍스트 문법: !`command` (실행 후 결과가 삽입됨)
- 예: !`git status`, !`gh pr diff`, !`npm list`
- 옵션: 필요 없음 / 있음 (명령어 지정)

**질문 4 - 확장 생각(Extended Thinking)**:
- "깊은 분석이 필요한 스킬인가요?"
- 예 -> 콘텐츠에 "ultrathink" 키워드 포함
- 아니오 -> 일반 처리

### 콘텐츠 작성 원칙
- 명확하고 구체적인 지시사항
- 단계별 구조 (번호 매기기)
- $ARGUMENTS, $0, $1 등 변수 적절히 활용
- 500줄 이내 유지 (초과 시 보조 파일로 분리)

### 자가 검증 체크리스트
```
Stage 4 검증:
[ ] 지시사항이 명확하고 모호함 없음
[ ] $ARGUMENTS 변수가 올바르게 배치됨
[ ] 동적 컨텍스트 !`cmd` 명령어가 유효함
[ ] 출력 형식이 명시됨
[ ] 콘텐츠 길이가 500줄 이내
[ ] Stage 2의 스킬 유형과 콘텐츠 일치
[ ] Stage 3의 allowed-tools와 콘텐츠 내 도구 사용 일치
```

## STAGE 5: 초마지막 - 보조 파일 추가 (50% -> 62.5%)

### 목표
필요한 경우 보조 파일(템플릿, 레퍼런스, 스크립트 등)을 추가합니다.

### 수집할 정보 (AskUserQuestion 사용)

**질문 1 - 보조 파일 필요 여부**:
- Stage 2에서 "단순"이면 건너뛸 수 있음을 안내
- "추가할 보조 파일이 있나요?" (복수 선택)
- 옵션:
  - 템플릿 (template.md) - Claude가 채워넣을 양식
  - 레퍼런스 (reference.md) - 상세 참조 문서
  - 예시 (examples/) - 기대 출력 예시
  - 스크립트 (scripts/) - 실행 가능한 도구
  - 불필요 (건너뛰기)

**질문 2 - 각 보조 파일 내용** (필요한 경우):
- 선택한 각 파일 유형에 대해 내용 수집

**질문 3 - SKILL.md 내 참조 연결**:
- 보조 파일을 SKILL.md에서 어떻게 참조할지 확인
- 형식: "상세 정보는 [reference.md](reference.md) 참조"

### 디렉토리 구조 확정
```
{skill-name}/
├── SKILL.md              # 메인 지시사항 (필수)
├── template.md           # 템플릿 (선택)
├── reference.md          # 레퍼런스 (선택)
├── examples/
│   └── sample.md         # 예시 (선택)
└── scripts/
    └── helper.py         # 스크립트 (선택)
```

### 자가 검증 체크리스트
```
Stage 5 검증:
[ ] 보조 파일 필요 여부 결정됨
[ ] 각 보조 파일 내용 작성됨
[ ] SKILL.md에서 보조 파일 참조 올바름
[ ] 디렉토리 구조 일관적
[ ] 스크립트 있다면 실행 가능 여부 확인
```

## STAGE 6: 중마지막 - 테스트 및 검증 (62.5% -> 75%)

### 목표
생성된 스킬을 실제로 검증합니다.

### 검증 항목

**1. 파일 구조 검증**:
- Glob으로 모든 파일 존재 확인
- Read로 각 파일 내용 확인

**2. Frontmatter 유효성**:
- YAML 문법 오류 확인
- 필수 필드 존재 확인
- 값 유효성 확인 (name 규칙, 도구 이름 등)

**3. 콘텐츠 검증**:
- $ARGUMENTS 자리표시자 올바른지 확인
- 동적 컨텍스트 !`cmd` 실행 가능 여부
- 마크다운 문법 유효성
- 보조 파일 링크 유효성

**4. 호출 테스트** (AskUserQuestion):
- "스킬을 테스트 호출해볼까요?"
- 예 -> /{skill-name}으로 실제 호출
- 아니오 -> 건너뛰기

### 자가 검증 체크리스트
```
Stage 6 검증:
[ ] 모든 파일이 올바른 위치에 존재
[ ] YAML frontmatter 문법 유효
[ ] 마크다운 콘텐츠 정상
[ ] 변수 치환 올바름
[ ] 보조 파일 참조 유효
[ ] 호출 테스트 통과 (선택)
```

## STAGE 7: 끝마지막 - 배포 완료 (75% -> 87.5%)

### 목표
스킬을 최종 배치하고 완료합니다.

### 수행 항목

**1. 최종 파일 확인**:
- 결정된 위치에 모든 파일이 올바르게 저장됨을 확인

**2. 버전 관리** (AskUserQuestion):
- "스킬을 git에 커밋할까요?"
- 예 / 아니오 / 나중에

**3. 배포 범위** (AskUserQuestion):
- "추가 배포가 필요한가요?"
- 옵션:
  - 현재 상태로 완료
  - ~/.claude/skills/에도 복사 (개인용 전역 등록)
  - 플러그인으로 패키징
  - 팀 공유

**4. 완료 요약 생성**:
```
 ╔═══════════════════════════════════╗
 ║     스킬 생성 완료 요약           ║
 ╠═══════════════════════════════════╣
 ║ 이름:  {name}                    ║
 ║ 위치:  {path}                    ║
 ║ 유형:  {type}                    ║
 ║ 호출:  /{name} {argument-hint}   ║
 ║ 파일:  {count}개                 ║
 ╚═══════════════════════════════════╝
```

### 자가 검증 체크리스트
```
Stage 7 검증:
[ ] 파일이 최종 위치에 저장됨
[ ] git 커밋 여부 결정/실행됨
[ ] 배포 범위 확인됨
[ ] 완료 요약이 정확함
```

## STAGE 8: 자가검토 - 최종 품질 리뷰 (87.5% -> 100%)

### 목표
전체 스킬을 종합적으로 리뷰하고 최종 품질을 확인합니다.

### 종합 리뷰 체크리스트

**A. 기능 완전성 (Completeness)**:
```
[ ] 스킬 목적이 콘텐츠에 완전히 반영됨
[ ] 모든 사용 시나리오가 커버됨
[ ] 엣지 케이스 처리 여부
[ ] 에러 상황 가이드 포함 여부
```

**B. 일관성 (Consistency)**:
```
[ ] frontmatter와 콘텐츠 일관적
[ ] 호출 방식과 내용 매칭
[ ] 인자 구조와 사용 일치
[ ] 보조 파일 참조 모두 유효
```

**C. 품질 (Quality)**:
```
[ ] 지시사항 명확, 모호하지 않음
[ ] 불필요한 내용 없음 (간결성)
[ ] 마크다운 포맷팅 깔끔
[ ] 재사용 가능한 구조
```

**D. 확장성 (Extensibility)**:
```
[ ] 향후 기능 추가 용이한 구조
[ ] 보조 파일 추가 가능
[ ] 다른 스킬과 연계 가능
```

**E. 보안 (Security)**:
```
[ ] 위험한 명령어 없거나 적절히 제한됨
[ ] allowed-tools 최소 권한 원칙 준수
[ ] 동적 컨텍스트 명령어 안전
```
