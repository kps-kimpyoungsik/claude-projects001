# 1. 프로젝트 분석 단계 - 프롬프트 패턴

## 목적
- 코드베이스 구조 이해
- 현존 문제점 및 이슈 파악
- 아키텍처 현황 분석
- 기술 스택 검토

## 4단계 분석 프로세스

### Phase 1: 코드베이스 전체 탐색
```
먼저 현재 프로젝트의 전체 구조를 파악해주세요.
- 프로젝트 디렉토리 레이아웃 (폴더 구조)
- 주요 설정 파일들 (package.json, tsconfig.json, vite.config.ts 등)
- 핵심 진입점 (main.tsx, App.tsx 등)
- 현재 기술 스택 및 버전
```

### Phase 2: 아키텍처 및 패턴 파악
```
프로젝트의 아키텍처를 분석해주세요:
- 폴더 구조에 적용된 아키텍처 패턴 (FSD, Clean, 등)
- 라우팅 구조 (어떻게 페이지들이 연결되는가)
- 상태 관리 방식 (Context, State, etc)
- 컴포넌트 계층 구조 및 의존성
```

### Phase 3: 현존 문제점 파악
```
현재 코드베이스에서 문제가 될 만한 부분들을 찾아주세요:
- 개선 가능한 코드 패턴
- 기술 부채 영역
- 성능 이슈 가능성
- 테스트 커버리지 부족 영역
- 보안 취약점 가능성
```

### Phase 4: 분석 결과 요약
```
분석 결과를 다음 형식으로 정리해주세요:
1. 현재 상태 (현황)
2. 주요 강점
3. 개선 필요 영역
4. 추천 조치사항
```

## 분석 체크리스트

- [ ] 디렉토리 구조 및 파일 조직 확인
- [ ] package.json 의존성 검토
- [ ] 빌드 설정 확인
- [ ] 라우팅 구조 파악
- [ ] 상태 관리 패턴 식별
- [ ] API 호출 방식 검토
- [ ] 에러 핸들링 패턴 확인
- [ ] 테스트 구조 평가
- [ ] 문서 및 주석 충분성 검토
- [ ] 보안 설정 확인
