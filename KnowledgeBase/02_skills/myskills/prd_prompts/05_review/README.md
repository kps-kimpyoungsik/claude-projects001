# 5. 검토 단계 - 프롬프트 패턴

## 목적
- 코드 리뷰
- 설계 검토
- 성능 검토
- 보안 검토
- 접근성 검토
- 문서 검토
- 최종 검증

## 5단계 검토 프로세스

### Phase 1: 변경사항 파악
```
다음을 검토 전에 파악해주세요:
- 변경된 파일 목록
- 각 파일의 변경 사항
- 변경 이유 및 배경
- 영향을 받는 다른 모듈
- 기존 테스트 통과 여부
```

### Phase 2: 코드 품질 검토
```
다음 기준으로 코드를 검토해주세요:
- 명명 규칙 준수 여부
- 코드 스타일 일관성
- 복잡도 평가 (순환/인지)
- 중복 코드 여부
- 타입 안전성
- 에러 처리
```

### Phase 3: 아키텍처 검토
```
다음을 검토해주세요:
- 설계 원칙 준수 여부
- 의존성 관리 (순환 의존성 등)
- 컴포넌트 책임 명확성
- 확장성 고려
- 재사용성
- 변경 영향도
```

### Phase 4: 성능 & 보안 검토
```
다음을 검토해주세요:
- 성능 영향 (렌더링, 번들 크기 등)
- 보안 취약점 (XSS, CSRF, SQL Injection 등)
- 접근성 준수
- 메모리 누수 가능성
- API 보안
```

### Phase 5: 검토 의견 및 추천
```
다음을 정리해주세요:
- 주요 문제점 (Must Fix)
- 개선 권고사항 (Should Consider)
- 좋은 점 (Positive Feedback)
- 차후 개선 사항 (Nice to Have)
- 병합 승인 여부
```

## 검토 체크리스트

### 전체 평가
- [ ] 변경사항이 명확한가
- [ ] 요구사항을 충족하는가
- [ ] 테스트가 충분한가
- [ ] 문서가 최신인가

### 코드 품질
- [ ] 코드 스타일 일관성
- [ ] 명명 규칙 준수
- [ ] 주석/문서 충분성
- [ ] DRY 원칙 준수
- [ ] KISS 원칙 준수

### 기능성
- [ ] 모든 경로 작동하는가
- [ ] 에러 처리가 완전한가
- [ ] 엣지 케이스 처리되는가
- [ ] 성능 저하 없는가

### 타입 안전성
- [ ] TypeScript 타입 정확한가
- [ ] any 타입 사용 최소화
- [ ] 제네릭 활용 적절한가
- [ ] 타입 가드 있는가

### 테스트
- [ ] 단위 테스트 있는가
- [ ] 통합 테스트 있는가
- [ ] 커버리지 충분한가
- [ ] 엣지 케이스 테스트 있는가

### 성능
- [ ] 불필요한 렌더링 없는가
- [ ] 번들 크기 증가 최소화
- [ ] 메모리 누수 없는가
- [ ] API 호출 최적화되었는가

### 보안
- [ ] XSS 방지되는가
- [ ] CSRF 방지되는가
- [ ] 입력 검증 있는가
- [ ] 민감정보 노출 없는가

### 접근성
- [ ] 키보드 네비게이션 가능한가
- [ ] ARIA 속성 올바른가
- [ ] 색상 대비 충분한가
- [ ] 스크린 리더 호환 가능한가

### 문서
- [ ] README 업데이트되었는가
- [ ] API 문서 업데이트되었는가
- [ ] 변경 로그 작성되었는가
- [ ] 마이그레이션 가이드 있는가 (필요시)
