# 테스트 단계 - 최적화된 프롬프트 패턴

## 패턴 1: 단위 테스트 작성
```
"<컴포넌트/함수명>의 단위 테스트를 작성해주세요.

테스트 대상:
- 파일 경로: <경로>
- 대상 항목: <컴포넌트명 또는 함수명>

테스트 프레임워크:
- <Jest/Vitest/etc>
- 라이브러리: <React Testing Library/etc>

테스트 케이스:
1. 정상 케이스 (Happy Path):
   - <입력> → <예상 출력>

2. 경계값 테스트:
   - <경계값> → <예상>

3. 에러 케이스:
   - <에러 조건> → <예상>

4. Props 조합:
   - <Props 조합> → <예상>

구현 기준:
1. AAA 패턴 (Arrange-Act-Assert)
2. 명확한 테스트 설명
3. 모킹 활용 (필요시)
4. 스냅샷 테스트 (필요시)

완성된 테스트 코드를 제공해주세요."
```

## 패턴 2: 컴포넌트 테스트 시나리오
```
"<컴포넌트명> 컴포넌트에 대한 테스트 시나리오를 작성해주세요.

컴포넌트 정보:
- 파일 경로: <경로>
- Props: <Props 목록>
- 상태: <상태 항목>
- 이벤트: <이벤트 목록>

테스트 시나리오:
1. 렌더링 테스트:
   - 올바르게 렌더링되는가
   - Props 기본값 설정

2. Props 변경 테스트:
   - Props 변경 시 재렌더링
   - 조건부 렌더링

3. 이벤트 테스트:
   - 클릭 이벤트 처리
   - 입력값 변경
   - 콜백 호출

4. 상태 변경 테스트:
   - 상태 변경 작동
   - 렌더링 업데이트

5. 에러 처리 테스트:
   - 잘못된 Props 처리
   - API 오류 처리

Jest/Vitest 코드로 작성해주세요."
```

## 패턴 3: API 모킹 및 통합 테스트
```
"API 통합 테스트를 작성해주세요.

API 정보:
- 엔드포인트: <URL>
- 메서드: <GET/POST/etc>
- 요청: <Request 구조>
- 응답: <Response 구조>

테스트 시나리오:
1. 성공 응답:
   - API 호출 성공 시 처리

2. 오류 응답:
   - 4xx, 5xx 에러 처리
   - 타임아웃 처리

3. 로딩 상태:
   - 로딩 중 UI 표시
   - 로딩 완료 후 데이터 표시

4. 데이터 검증:
   - 응답 데이터 검증
   - 데이터 변환 검증

구현 방식:
- Mock Service Worker (msw) 또는 jest.mock
- 성공 시나리오
- 실패 시나리오
- 엣지 케이스

완성된 테스트 코드를 제공해주세요."
```

## 패턴 4: 성능 테스트
```
"성능 테스트를 구성해주세요.

테스트 대상:
- 파일 경로: <경로>
- 성능 항목: <렌더링/번들/메모리 등>

측정 항목:
1. 렌더링 성능:
   - 초기 렌더링 시간
   - 리렌더링 시간
   - 프레임율

2. 번들 크기:
   - 전체 번들 크기
   - 청크 크기
   - 불필요한 의존성

3. 메모리:
   - 메모리 사용량
   - 메모리 누수 확인

4. 이미지/자산:
   - 이미지 최적화
   - 불필요한 자산

테스트 코드:
- React DevTools Profiler 사용
- Lighthouse 실행
- Bundle Analyzer 실행

결과 분석:
- 성능 지표
- 병목 지점
- 개선 추천"
```

## 패턴 5: 접근성 테스트
```
"접근성 테스트를 구성해주세요.

테스트 대상:
- 파일 경로: <경로>
- 컴포넌트: <컴포넌트명>

테스트 항목:
1. 키보드 네비게이션:
   - Tab 키로 모든 요소 접근 가능
   - 초점 순서 논리적
   - 포커스 표시 명확

2. ARIA 속성:
   - aria-label 검증
   - aria-describedby 검증
   - 역할(role) 설정 검증

3. 색상 대비:
   - WCAG AA 기준 만족
   - WCAG AAA 기준 (권장)

4. 이미지 alt 텍스트:
   - 모든 이미지에 alt 텍스트
   - 의미 있는 alt 텍스트

5. 폼 관련:
   - 레이블과 입력 필드 연결
   - 에러 메시지 명확
   - 필수 필드 표시

테스트 도구:
- axe DevTools
- WAVE
- Jest axe
- 수동 스크린 리더 테스트

테스트 코드와 체크리스트를 제공해주세요."
```

## 패턴 6: 수동 테스트 가이드
```
"수동 테스트 가이드를 작성해주세요.

테스트 범위:
- 기능: <테스트할 기능>
- 브라우저: <대상 브라우저>
- 디바이스: <데스크톱/모바일>

테스트 환경 설정:
1. 필수 라이브러리 설치
2. 데이터 준비 방법
3. 서버 시작 방법

테스트 시나리오:
1. 정상 흐름:
   - 단계별 절차
   - 각 단계 예상 결과

2. 에러 케이스:
   - 에러 발생 방법
   - 예상 에러 메시지

3. 엣지 케이스:
   - 경계값 테스트
   - 특수한 입력값

검증 항목:
- 화면 표시 정확성
- 사용자 상호작용 정확성
- 에러 처리 정확성
- 성능 (느려짐 없음)
- 접근성 (스크린 리더, 키보드)

체크리스트 형식으로 제시해주세요."
```

## 패턴 7: E2E 테스트
```
"E2E 테스트를 작성해주세요.

테스트 프레임워크:
- <Cypress/Playwright/Selenium>

테스트 시나리오:
- 사용자 경로: <경로 설명>
- 시작점: <URL/페이지>
- 종료점: <예상 결과 페이지>

단계별 테스트:
1. [초기 상태]
   - 페이지 로드
   - 초기 요소 확인

2. [사용자 액션]
   - 클릭
   - 입력
   - 제출

3. [상태 변화]
   - 데이터 로드
   - 페이지 네비게이션
   - 상태 업데이트

4. [결과 검증]
   - 예상 데이터 표시
   - 에러 메시지 (필요시)
   - 최종 상태

테스트 코드 (Cypress/Playwright):
- 명확한 셀렉터
- 대기 처리 (implicit/explicit)
- 스크린샷/비디오 캡처
- 주석"
```

## 패턴 8: 테스트 커버리지 분석
```
"테스트 커버리지를 분석해주세요.

대상:
- 파일/폴더: <경로>

분석 항목:
1. 현재 커버리지:
   - Line Coverage %
   - Branch Coverage %
   - Function Coverage %
   - Statement Coverage %

2. 미커버 영역:
   - 테스트되지 않은 코드
   - 테스트 가능성

3. 우선순위:
   - 높은 우선순위 (비즈니스 핵심)
   - 중간 우선순위 (일반 로직)
   - 낮은 우선순위 (엣지 케이스)

4. 개선 계획:
   - 필요한 테스트
   - 예상 작업량
   - 장기 목표

HTML 리포트와 분석 문서를 제공해주세요."
```

## 산출물

테스트 단계에서 생성할 산출물:

1. `<component>.test.tsx` - 컴포넌트 단위 테스트
2. `<feature>.test.ts` - 기능 단위 테스트
3. `<component>.integration.test.tsx` - 통합 테스트
4. `e2e-tests.spec.ts` - E2E 테스트
5. `test-scenarios.md` - 테스트 시나리오
6. `manual-testing-guide.md` - 수동 테스트 가이드
7. `test-coverage-report.md` - 커버리지 리포트
8. `performance-test-results.md` - 성능 테스트 결과
