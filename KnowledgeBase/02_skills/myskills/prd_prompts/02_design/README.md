# 2. 설계 단계 - 프롬프트 패턴

## 목적
- 아키텍처 설계
- 컴포넌트 구조 설계
- API/인터페이스 설계
- 데이터 흐름 설계
- 스타일 시스템 설계

## 5단계 설계 프로세스

### Phase 1: 요구사항 정의
```
개발할 기능/모듈에 대해 다음을 정의해주세요:
- 기능의 목적 및 범위
- 사용자 스토리 (누가, 언제, 왜)
- 성공 기준 (Definition of Done)
- 제약조건 (성능, 브라우저 지원 등)
- 의존성 (다른 기능과의 관계)
```

### Phase 2: 아키텍처 설계
```
다음을 고려하여 아키텍처를 설계해주세요:
- 컴포넌트 계층 구조
- 데이터 흐름 (단방향 vs 양방향)
- 상태 관리 전략
- API 호출 패턴
- 에러 핸들링 전략
```

### Phase 3: 상세 설계
```
다음 수준의 상세 설계를 진행해주세요:
- 각 컴포넌트의 Props/State 정의
- 함수 시그니처 및 반환값
- 조건부 렌더링 로직
- 이벤트 핸들러 흐름
- CSS 구조 및 명명 규칙
```

### Phase 4: 인터페이스 정의
```
다음을 명확히 정의해주세요:
- 컴포넌트 Props 인터페이스 (TypeScript)
- API 요청/응답 형식
- 상태 객체 구조
- 커스텀 훅 시그니처
```

### Phase 5: 검토 및 최적화
```
설계를 다음 관점에서 검토해주세요:
- 확장성: 새 기능 추가 시 얼마나 용이한가
- 재사용성: 다른 곳에서 재사용 가능한가
- 성능: 렌더링 최적화 가능한가
- 테스트 가능성: 단위 테스트 작성 용이한가
- 유지보수성: 코드 이해와 수정이 용이한가
```

## 설계 체크리스트

### 기능 설계
- [ ] 기능 범위 명확히 정의됨
- [ ] 사용자 스토리 작성됨
- [ ] 성공 기준 정의됨
- [ ] 제약조건 파악됨

### 아키텍처 설계
- [ ] 컴포넌트 계층 구조 정의됨
- [ ] 데이터 흐름 결정됨
- [ ] 상태 관리 방식 정해짐
- [ ] API 패턴 정해짐

### 상세 설계
- [ ] Props/State 정의됨
- [ ] 함수 시그니처 정해짐
- [ ] 렌더링 로직 설계됨
- [ ] 에러 처리 방식 정해짐

### 타입 정의
- [ ] TypeScript 인터페이스 설계됨
- [ ] 제네릭 활용 계획됨
- [ ] 유니온 타입 고려됨

- [ ] 테마/변수 시스템 설계됨
