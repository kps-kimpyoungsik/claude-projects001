## 프롬프트 원문

```
ai-project-system 프로젝트를 처음(신규 프로젝트 시작 지점)부터 끝까지 단계별로,
화면·기능·설정 요소 하나하나를 실측(코드·API·DB 실제 조회 — 추정 금지)해서 검토한다.

## 1. 실측 범위 (요소 단위 — 빠짐없이)
- 화면 단위: LNB 각 메뉴(프로젝트 설정/등록, 문서 등록·청킹, 요구사항 관리, 청크 위치추적,
  Task 배차·상태관리, 프로젝트 현황 대시보드, 플랫폼 공통) 전부를 하나씩 순회.
- 각 화면 내부의 "선택 요소"(드롭다운·라디오·체크박스)와 "입력 요소"(텍스트·파일업로드·
  날짜 등)를 개별적으로 실측 — 기능이 실제로 백엔드 API와 연결돼 동작하는지, 아니면
  화면만 있고 처리가 없는(dead UI) 상태인지 하나씩 확인.
- 각 화면의 데이터 시각화(차트·진행률바·카드·표)가 **원본 데이터(실제 requirements_store,
  documents, task_locks 등)를 그대로 반영**하는지, 아니면 하드코딩·목업·부정확한 집계인지 확인.

## 2. 개선 목표 (실측 후 발견된 각 항목에 대해)
- 구현이 미미하거나 절반만 된 기능은 **완성**한다(반쪽 구현 방치 금지).
- 데이터 시각화는 **원본 데이터 기반으로 정확하게** — 집계 로직이 실제 스토어와 일치하는지
  검증하고, 불일치가 있으면 근본원인부터 고쳐서 반영한다.
- 각 선택/입력 요소는 사용자가 **한눈에 이해할 수 있도록** 더 자세한 설명(라벨·툴팁·placeholder)과
  더 명확한 시각적 구분(그룹핑·강조·상태표시)을 갖추도록 개선한다.
- 전체 화면 흐름이 사용자의 실제 사용 패턴(마법사식 등록 → 목록 확인 → 상세 검토 → 배차/현황)에
  맞게 최적화되도록 UX 관점에서 재검토한다.

## 3. 작업 진행 방식 (충돌·안전 강제)
- 실측 결과를 화면/기능 단위로 태스크로 쪼개고, 각 태스크의 **정확한 파일 범위(impact_scope)를
  먼저 확정**한 뒤 착수한다 — 범위 미확정 상태로 병렬 착수 금지.
- 태스크 간 파일 범위가 겹치는지(§PCM N×N 매트릭스) 매번 검증하고, 겹치지 않는 것만 병렬로
  동시에 진행한다. 겹치는 태스크는 순서를 정해 순차로 처리한다.
- 착수 전 이 프로젝트의 claim/작업이력을 조회해, 다른 세션이 이미 진행 중이거나 최근에 건드린
  영역인지 확인한 뒤 겹치지 않게 진행한다(다른 세션 영역은 침범하지 않고 우회하거나 위임 표시).
- 진행 중 오류·회귀·검증 실패가 발견되면 멈추지 말고 근본원인을 확인해 가역 범위 내에서
  직접 해결한 뒤 계속 진행한다(단, 삭제·정본·헌법·서비스배포처럼 되돌리기 어려운 조치는
  사용자 승인 없이 진행하지 않는다).
- 한 태스크를 완결(검증 통과)한 뒤에만 다음 태스크로 넘어간다 — 여러 태스크를 동시에 미완 상태로
  벌여놓지 않는다(진행 상황이 항상 명확한 재개 지점을 갖도록).
- 목표(전체 요소 실측 + 개선)가 끝날 때까지, 또는 더 이상 안전하게 진행할 수 있는 항목이 없을
  때까지(비가역 항목만 남으면 그것들을 모아 한 번에 승인 요청) 멈추지 않고 이어서 진행한다.

## 4. 노하우 자산화 (다음 작업에 재사용 가능하도록)
- 이 진행 과정에서 얻은 노하우(효율적인 태스크 분해 방법·자주 겹치는 파일 패턴·반복되는
  버그 유형·검증 방법)를 정리해, 다음에 비슷한 전체 점검 작업을 할 때 처음부터 다시 알아내지
  않아도 되도록 지식 자산으로 남긴다(신규 문서 남발이 아니라, 이미 있는 관련 자산이 있으면
  거기에 보강하는 방식으로).
- 이렇게 쌓인 노하우가 다음 세션에서도 자동으로 인지되어, 작업 분배와 충돌 방지를 더 효율적으로
  할 수 있도록 만든다.
```

## 참고 (이 프롬프트를 만들 때 근거로 삼은 맥락)

- 이 문서는 `00_PROJECT_CONSTITUTION.md`(요구사항 기반 AI 개발 태스크 관리 시스템이라는 프로젝트
  본연의 목적)와 어긋나지 않는 범위 — UI/UX·데이터 시각화·기능 완성도 점검은 프로젝트 자체의
  품질 개선이지 목적 이탈이 아니다.
- "충돌 없이 병렬"·"완결 후 다음 태스크"·"진행 중 문제 자율 해결"·"노하우 자산화" 요청은 이
  세션이 이미 반복적으로 적용해 온 표준 작업 방식(§PCM 충돌 매트릭스, 순차완결 원칙, 실패 자율
  해결 루프, 지식자산 등재)을 그대로 문장으로 풀어 쓴 것 — 실행 시 별도 설명 없이 자동 적용된다.
