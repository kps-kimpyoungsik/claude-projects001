## 1. 원칙

| # | 원칙 | 뜻 |
|---|---|---|
| P1 | **버리는 곳마다 기록한다** | 자료가 줄거나 바뀌는 모든 지점이 이력을 남긴다. 기록 없는 삭제 = 버그 |
| P2 | **정형 결과는 파생물이다** | 정제본 = f(원본 데이터셋, 정제 계획, 사람 결정). 언제든 다시 만들 수 있고, 원본은 바뀌지 않는다 |
| P3 | **사람 결정이 자동 판단을 이긴다** | 복원·직접 수정은 결정으로 남아 다시 정제해도 유지된다 |
| P4 | **항목·분류는 자료에서 나온다** | 컬럼 수, 자료 묶음(분류) 수, 범주 값 목록은 고정 목록이 아니라 들어온 자료에 따라 1개~N개 |
| P5 | **개인정보는 이력에서도 지킨다** | 이력의 값도 저장 규칙(가명 토큰 · 본문 이름 가림)을 거친다. 고유식별정보는 값 없이 "차단됨"만 남긴다 |

## 2. 자료가 사라지는 지점 (코드 실측)

| 단계 | 지점 | 이전 | 이제 기록하는 이름(op) |
|---|---|---|---|
| 적재 | 헤더 위의 제목·메타 행 | 흔적 없이 버림 | `PRE_HEADER_ROW` |
| 적재 | 헤더 폭 밖의 칸 | 버리지 않음 — 격자가 최대 폭으로 채워져 자동 이름 열(colN)로 들어간다(테스트 실측) | — |
| 적재 | 표로 판정되지 않은 시트 | 건너뜀 | `SHEET_SKIPPED` |
| 적재 | 고유식별정보(주민번호 등) | 차단값으로 교체 | `PII_BLOCKED` (값은 남기지 않음) |
| 정제 | 결측 표기(`-`, `N/A`) | 빈 값 | `NORMALIZE_NULL` |
| 정제 | 완전히 같은 행 | 제거 | `DEDUPE_ROWS` |
| 정제 | 공백·날짜·숫자 표기 | 값 변환 | `TRIM_SPACE` · `DATE_*` · `NUMBER_UNFORMAT` (변환 전 값 보존) |
| 정제 | 빈 열 | 제거 | 값이 없어 잃는 것 없음 — 계획에만 표시 |
| 판정 | 격리(REJECTED) | 목록에서 숨김 | 행은 그대로 보존(기존) |

## 3. 저장 구조

```
refine_trace     — 사라지거나 바뀐 것 한 건당 한 행
  dataset_id  결과 데이터셋 (적재=그 데이터셋, 정제=정제본, 건너뛴 시트=업로드 배치)
  source_id   근거 (정제=원본 데이터셋, 적재=파일/시트)
  stage       INGEST | REFINE | EDIT
  op, row_ref(원본 행 번호), col_name, before_v, after_v(null=삭제)

refine_decision  — 사람 결정. 다시 정제해도 유지된다
  source_id, op, col_name('' = 모든 열), row_ref(-1 = 모든 행), action=KEEP(그 정제를 하지 않음)
```

직접 수정은 **원본 데이터셋의 칸**을 고치고 `EDIT` 이력(바꾸기 전·후)을 남긴 뒤 정제본을 다시 만든다.
정제본을 직접 고치면 다음 정제 때 사라지기 때문이다(P2). 되돌리기 = 이력의 이전 값으로 다시 수정.

## 4. 동적 항목·분류

- **항목(컬럼)**: 헤더 탐지 결과대로 1개~N개. 헤더가 없으면 col1…colN.
- **분류(자료 묶음)**: 컬럼 이름 집합이 비슷한(자카드 ≥ 0.5) 데이터셋끼리 자동으로 묶는다. 묶음 수는 자료에 따라 정해진다.
  같은 양식을 매주 올리면 한 묶음으로 모인다.
- **범주 값**: 범주 역할 열의 값 목록은 자료에서 뽑는다(고정 코드표 없음).

## 5. 추가 자료로 재검증

새 파일을 올리면 기존 파이프라인이 돌고, 그 데이터셋은 비슷한 묶음에 들어간다. 묶음 "재검증"은
**묶음 전체 행을 모아서** 컬럼 역할을 다시 판단하고, 각 데이터셋의 정제 계획을 다시 세운다. 표본이 늘어 판단이 달라진
데이터셋은 "달라짐"으로 표시한다. 자료가 많을수록 판단이 안정된다 — 한 파일 10행으로는 범주인지 본문인지 애매한 열도
여러 파일을 합치면 분명해진다.

## 6. 헤더 다시 지정 (적재 재실행)

헤더를 잘못 골라 제목 행이 사라졌거나 데이터 행이 헤더가 됐으면, 봉인 원본을 개인키로 임시 파일에 풀어 **헤더 행을 지정해**
같은 데이터셋 ID로 다시 적재한다. 임시 파일은 바로 지운다. 개인키가 없는 서버에서는 거절한다.
