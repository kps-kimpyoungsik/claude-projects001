선행: `plans/_opens/dataset_dynamic_system/` (DDS — Phase 1·2 구현 완료)
인스턴스: [`10_사례_견적서.md`](10_사례_견적서.md) — 이 뼈대의 **적용 사례 1번**

## 1. 무엇을 만드는가

> **기준이 있으면 그 기준대로, 기준이 없으면 쌓인 표준으로, 그것도 없으면 물어서** —
> 어떤 비정형 정보든 **출처를 잃지 않은 채** 정형 데이터로 바꾸고,
> 그 정형 데이터에서 **필요한 형태의 정보를 다시 만들어낸다.**
> 그리고 **쓸수록 자동화 비율이 올라간다.**

견적서는 이 엔진의 인스턴스 하나다. 계약서·검수확인서·주간보고·제안서·시방서·WBS·결함대장
— 기준 문서 1개만 주면 같은 파이프라인이 돈다.

### 1.1 "기준"의 정의 — 4종, 전부 1급 입력이다

사용자가 줄 수 있는 것은 네 가지 모양이고, **네 개 모두 같은 목적지(표준 정의)로 수렴**한다.

| 기준 종류 | 실체 | 무엇을 얻어내나 | 얻기 쉬운 정도 |
|---|---|---|---|
| **포맷** | JSON Schema · DDL · API 명세 · CSV 헤더 정의 | 필드·타입·제약이 **명시**돼 있다 → 거의 직독 | ★★★★★ |
| **템플릿** | 빈 양식 (xlsx·docx·pptx·md) | 라벨 + 값이 들어갈 **자리**(앵커) | ★★★★ |
| **예시** | 채워진 실제 문서 1~N건 | 라벨 + **값 사례** → 타입·포맷·코드값까지 역추론 | ★★★ |
| **가이드** | 서술형 작성 지침 문서 | 규칙·필수여부·단위·금지사항이 **문장 속**에 있다 | ★★ |

**핵심 결정 (Q-A1 계승)**: 네 종류 모두 결국 `standard_dataset` + `standard_field` 를 만든다.
기준마다 다른 것은 **유도 방법(어댑터)**뿐이고, 만들어지는 것은 하나다.
→ 기준 종류가 늘어도 하부 엔진(바인딩·학습·승인·투영)은 손대지 않는다.

### 1.2 기준이 없을 때 — 3단 폴백

```
① 사용자가 준 기준이 있다          → 그 기준으로 표준 유도 (SPEC 층)
② 없다 → 누적된 표준 중 유사한 것  → 컬럼·용어 시그니처 매칭으로 후보 제시 + 사람 선택
③ 그것도 없다                      → 데이터에서 표준 **초안**을 역유도 → 사람 승인 후 신규 표준 등재
```

②·③은 **자동으로 확정하지 않는다.** 표준은 이후 모든 데이터의 기준이 되므로, 잘못 선 표준
하나가 누적 전체를 오염시킨다(DDS 핵심결정 7 "표준은 승인 없이 못 바꾼다" 그대로).

## 2. 실측 — DDS 대비 진짜로 새로운 것은 셋뿐

DDS(`dataset_dynamic_system`)가 이미 **표준 뼈대·바인딩·학습·어휘·승인**을 구현해 두었다.
새 설계를 얹기 전에 **무엇이 이미 도는지** 셌다.

### 2.1 이미 있다 — 재사용 (실측 3,806줄 / 19테이블)

| 계층 | 자산 | USS에서의 역할 |
|---|---|---|
| 표준 정의 | `standard_dataset`·`standard_field`·`standard_relation` | **기준 4종의 공통 목적지** |
| 바인딩 | `BindingEngine` 372줄 — `classify/bind/correct/learn` | 컬럼·라벨 → 표준 필드 매핑 |
| 학습 | `binding_feedback` (col_norm×field, hits/human) | 자동화율 상승의 엔진 |
| 어휘 | `vocab_term` 112건 · `vocab_miss` | 동의어·코드값 해소 |
| 원천 단일성 | `Ingest.classify()` SOURCE/DERIVED/VALUE | 필드 중복 등재 차단 |
| 근거 | `dataset_binding.evidence/confidence/source` | 신뢰 표시의 1차 재료 |
| 6축 의미 | `domain/area/role/context/topic/link` + 3계층 에스컬레이션 설계 | 분야·영역 자동 분류 |
| 저장 | `dataset`·`dataset_column`·`dataset_row`(JSON) | 원자료 보관 |
| 기술 판정 | `00_연구조사` — 채택/미채택 15출처 | **재조사 불필요** |

### 2.2 없다 — 이번 설계의 전부

| # | 결핍 | 근거(실측) | 이게 없으면 |
|---|---|---|---|
| **N1** | **기준(Spec) 입력 경로 0** | 표준은 `StandardSeeder` 203줄로 **코드에 하드코딩 시드**. 사용자가 기준 문서를 주는 경로 없음 | 새 분야마다 개발자가 코드를 고쳐야 함 → "다양한 분야 누적" 불가 |
| **N2** | **비정형 입력 0 + 출처 좌표 0** | `UploadService` `.xlsx` 문자열 체크만. `dataset_row`는 `row_no`뿐 — 원본 어느 위치였는지 잃음 | 표가 아닌 정보는 못 먹고, 먹어도 근거를 못 보임 |
| **N3** | **정확도 측정 루프 0** | `binding_feedback`은 *횟수*만 센다. 맞았는지 틀렸는지, 자동화율이 오르는지 **아무도 모름** | "신뢰성 있게 누적"이 **주장에 그침**. 학습 승격 판단 근거 0 |

부가로 이전 사례 문서에서 잡은 것: 값 레벨 승인(G3)·질의 루프(G4)·문서 출력(G5).
이 셋은 N1~N3 위에 얹히는 **인스턴스 기능**이라 뼈대에서는 4층 중 PROJECT/ASK로 일반화한다.

> **N3가 이 설계에서 가장 중요하다.** N1·N2는 "할 수 있게" 만들고,
> N3만이 "**정말 나아지고 있는가**"를 알려준다. 측정 없는 학습은 학습이 아니라 축적이다.

## 3. 뼈대 — 4층 + 2개의 가로 루프

```
       ┌─────────────────────────────────────────────────────────────────┐
  기준 │ L1 SPEC      예시·가이드·템플릿·포맷  →  표준 정의(standard_*)   │
       │              4 어댑터 → 1 목적지 · 사람 승인 게이트              │
       └───────────────────────────┬─────────────────────────────────────┘
                                   │ 무엇을 채워야 하는가 (필드·타입·제약)
       ┌───────────────────────────▼─────────────────────────────────────┐
  자료 │ L2 EXTRACT   어떤 파일이든  →  조각(fragment) + **원본 좌표**     │
       │              xlsx docx pptx md txt (pdf·img 확장)                │
       └───────────────────────────┬─────────────────────────────────────┘
                                   │
       ┌───────────────────────────▼─────────────────────────────────────┐
  정형 │ L3 STRUCTURE 조각 → 「필드 = 값 + 출처 + 확신도 + 상태」          │
       │              R1 규칙 → R2 통계 → R3 임베딩 → R4 LLM (싼 것부터)  │
       │              충돌은 병합 않고 보존 · 미충족은 질의로             │
       └───────────────────────────┬─────────────────────────────────────┘
                                   │ 승인된 정형 데이터
       ┌───────────────────────────▼─────────────────────────────────────┐
  산출 │ L4 PROJECT   정형 → 필요한 형태  (문서·표·API·질의응답)          │
       │              출력 기준도 L1 표준 1건 → 필드 대 필드 투영          │
       └─────────────────────────────────────────────────────────────────┘

  ═══ 가로 루프 A: 학습 ═══  사람의 모든 교정·승인 → 라벨 → 다음 판정 개선
  ═══ 가로 루프 B: 측정 ═══  gold set 대비 정확도·자동화율을 **매 배치 기록**
```

**불변식 5개**

| # | 불변식 | 강제 지점 |
|---|---|---|
| I1 | 출처 없는 값은 존재할 수 없다 | `fact.frag_id` NOT NULL (사람 입력도 `kind=human` 조각 생성) |
| I2 | 승인 안 된 값은 산출물에 못 들어간다 | L4 진입 게이트 |
| I3 | 기준 밖으로 나가지 않는다 | L4는 표준 필드에 없는 값을 만들어내지 않는다 |
| I4 | 사람 판정은 자동이 덮지 못한다 | `source=human` 보존 (DDS ADR 계승) |
| **I5** | **측정되지 않은 개선은 채택하지 않는다** | 학습 사다리 승격은 §6 수치 조건 충족 시에만 |

## 4. L1 SPEC — 기준 4종 → 표준 1개 (N1 해소)

### 4.1 Port 1개 + Adapter 4개 (T102 NTM 블록 표준)

```java
public interface SpecAdapter {                       // Port
    boolean supports(SpecKind kind, String ext);
    StandardDraft derive(File spec, String domainHint);   // → 표준 초안
}
public record StandardDraft(
    String stdId, String name, String grain, String purpose,
    List<FieldDraft> fields,          // key·label·role·type·required·unit·codeSet·synonyms
    List<RelationDraft> relations,
    double coverage,                  // 기준에서 확정적으로 읽어낸 비율
    List<String> uncertain            // 사람 확인이 필요한 항목 — 숨기지 않는다
);
```

| Adapter | 유도 방법 | 확신도 | 미확정 처리 |
|---|---|---|---|
| **FormatAdapter** (포맷) | JSON Schema·DDL 직독. `required`·`type`·`enum`이 **그대로** 필드 제약 | 0.95+ | 라벨(한글 표기)만 사람이 붙임 |
| **TemplateAdapter** (템플릿) | 라벨 셀 탐지 → 인접 빈 칸 = 앵커. `{{key}}` 있으면 우선. 반복 구간 = 빈 행 2줄+ | 0.7~0.9 | 역할(role)·타입 추정치는 `uncertain` |
| **ExampleAdapter** (예시) | 라벨 + **값**까지 있으므로 타입·포맷·코드값 역추론. N건이면 **교집합=필수, 합집합=선택** | 0.8~0.95 | 1건뿐이면 필수 판정 불가 → 전부 선택 + 경고 |
| **GuideAdapter** (가이드) | 문장에서 규칙 추출: "반드시/필수" → required, "단위: 원" → unit, "A/B/C 중 하나" → codeSet | 0.4~0.7 | **R4(LLM) 의존도 가장 높음** → 전량 사람 검토 강제 |

**어댑터 간 합성이 기본이다** — 실무에서는 "템플릿 + 예시 3건 + 가이드 1부"가 같이 온다.
합성 규칙: **확신도 높은 쪽이 이기되, 충돌은 병합하지 않고 둘 다 남겨 사람이 고른다**(T115 SSI).

```
FormatAdapter(0.95) ─┐
TemplateAdapter(0.8) ─┼→ merge(충돌 보존) → StandardDraft → [사람 승인] → standard_dataset
ExampleAdapter(0.9)  ─┤                                        ↑
GuideAdapter(0.5)    ─┘                              DDS SAG 승인 워크플로 재사용
```

### 4.2 승인 게이트는 새로 만들지 않는다

DDS `06_후보자격_주부관계_승인관리.md` §4 SAG(자동 평가 5기준 80점 + 사람 승인 2단)가
이미 "표준 등재 승인"을 정의해 두었다. **그것을 그대로 호출한다.**
USS가 추가하는 것은 **입력 경로(어댑터)** 뿐이다.

## 5. L2 EXTRACT / L3 STRUCTURE — 요약 (상세는 사례 문서)

두 층의 구체 설계는 [`10_사례_견적서.md`](10_사례_견적서.md) §4 B2·B3에 이미 있다.
뼈대 수준에서 고정할 것만 적는다.

**L2 계약**: `Fragment(fragId, docId, locator, kind, text, confidence)`
- `locator` = 포맷 prefix + 원본 좌표 문자열 (`sheet:견적!C5` / `docx:p12.r3` / `pptx:s2.sh4` / `pdf:p3@[x,y,w,h]`)
- **포맷별 위치 테이블을 나누지 않는다** — 좌표계가 달라 정규화가 불가능하고, 문자열 1개가 확장에 열려 있다.

**L3 계약**: `Fact(caseId, fieldKey, lineNo, value, fragId, confidence, source, status, evidence)`
- `source ∈ {rule, stat, embed, llm, calc, human}` — DDS 3계층 에스컬레이션 + `calc` 추가
- `status ∈ {candidate, conflict, approved, rejected}`
- **충돌은 자동 병합 금지.** 둘 다 `conflict`로 남기고 사람이 고른다.

**질의(ASK)**: 미충족(required 공백) · 충돌 · 저확신(<0.6) 3종만 물어본다.
답변은 fact를 만들면서 **동시에 어휘·학습에 먹인다** — 같은 질문 2회는 설계 실패다.

## 6. 학습 사다리 — ML/DL을 언제 붙이는가 (수치로 못 박는다)

> **지금 학습 데이터는 0건이다.** 이 시스템의 첫 번째 산출물은 정형 데이터가 아니라
> **라벨**이다 — 사람의 승인·교정 하나하나가 지도학습 라벨이기 때문이다.
> 그러므로 딥러닝은 **출발점이 아니라 도착점**이고, 그 사이에 올라갈 계단이 있다.

| 단 | 방법 | 필요 자원 | **승격 조건 (이 조건 전엔 다음 단으로 안 감)** |
|---|---|---|---|
| **L0 규칙** | 컬럼명 사전·정규식·동의어 (`BindingEngine` 현행) | 없음 | 기본값 |
| **L1 통계** | 값 분포·Jaccard·c-TF-IDF (DDS 채택분) | 없음 (자바 내장) | L0 커버리지 < 80% 인 필드가 존재 |
| **L2 임베딩** | 라벨·값 문장 임베딩 → 코사인 근접 매칭 | 임베딩 모델 조달 (DDS 미결) + pgvector 또는 자바 코사인 | **L0+L1 커버리지 < 85%** 가 **3개 도메인 이상**에서 측정됨 |
| **L3 학습 모델** | 라벨 데이터로 분류기 학습(필드 매칭·레이아웃) | 라벨 + 학습 파이프라인 + 운영 | **라벨 ≥ 2,000건** ∧ **L2로도 못 잡는 비율 ≥ 15%** ∧ **오프라인 A/B에서 L2 대비 +5%p 이상** |

**세 단서** — 이걸 어기면 돈과 시간을 태운다.

1. **L3는 "정확도가 모자라서" 붙이는 것이지 "요즘 기술이라서" 붙이는 게 아니다.**
   승격 조건에 전부 **측정치**가 들어 있는 이유다(I5).
2. **L1/L2는 이미 DDS가 채택 판정한 것**이다(`00_연구조사` C계열). 다시 조사하지 않는다.
3. **LLM(R4)은 사다리와 별개의 보조축**이다 — 기본 OFF, 앞 단이 못 잡은 것만, 스키마 강제 + 검증.
   특히 GuideAdapter(서술문 → 규칙)는 LLM 의존도가 가장 높으므로 **전량 사람 검토**가 붙는다.

## 7. 신뢰성 누적 — 측정 루프 (N3 해소, 이 설계의 핵심 추가)

"점점 신뢰성 있게 누적된다"를 **주장이 아니라 수치**로 만든다.

### 7.1 Gold Set — 정답지를 따로 둔다

- 사람이 승인한 fact 중 **매 도메인 최소 50건**을 `gold=true`로 고정 보관(별도 테이블 아님, 플래그).
- gold는 **학습에 쓰지 않는다** — 쓰면 시험지를 보고 공부하는 꼴이 된다.
- 표준·사전이 바뀌면 gold를 **재평가만** 하고 값은 바꾸지 않는다(기준이 흔들리면 측정도 흔들린다).

### 7.2 매 배치마다 기록하는 4개 숫자

```
structuring_metric  batch_id, domain, std_id, measured_at,
                    coverage,      -- 필수 필드 중 값이 채워진 비율
                    auto_rate,     -- 사람 개입 없이 확정된 비율  ← "자동화가 오르는가"
                    precision,     -- gold 대비 자동 판정이 맞은 비율 ← "믿을 만한가"
                    ask_count      -- 사람에게 물은 횟수 ← "귀찮아지는가"
```

- **이 4개가 이 시스템의 성적표다.** 화면 1개(`/structuring/health`)로 도메인별 추이를 본다.
- **`precision`이 떨어지면 자동 확정 임계를 올린다**(더 많이 묻는다). 반대면 내린다.
  임계를 손으로 정하지 않고 **측정에 반응하게** 하는 것이 누적의 실체다.
- **회귀 감지**: 직전 배치 대비 `precision` −5%p 이상이면 **경고 + 원인 배치 지목**.
  사전·표준 변경이 과거를 망가뜨리는 사고를 여기서 잡는다(DDS 05 §5.3 3원칙과 짝).

### 7.3 도메인이 늘어날 때 — 격리가 기본

한 도메인에서 잘 맞는 규칙이 다른 도메인에서 틀리는 일이 반드시 생긴다(`잔액`이
회계에서는 measure, 인사에서는 연차 일수).
→ **학습 키는 `col_norm` 단독이 아니라 `(domain, col_norm)`** 으로 둔다.
DDS `binding_feedback`에 `domain` 컬럼 1개 추가로 해결한다. 전역 규칙은 **여러 도메인에서
동시에 확인된 것만** 승격한다(도메인 3개 이상).

## 8. 관계·그래프 — 데이터셋이 많아졌을 때 서로 참조하게 만들기

> **상세 정본: [`20_데이터셋_관계그래프.md`](20_데이터셋_관계그래프.md)** (2026-09-19 확정)

요청의 "지식그래프 vs GraphQL"은 경쟁 관계가 아니라 **다른 층**이다 — 판정 확정:

| | 판정 | 요약 |
|---|---|---|
| **지식그래프**(데이터 관계 맥락) | **채택** | 노드 5종(dataset·standard·term·**case**·column) × 엣지 7종. **저장 엔진은 관계 테이블로 시작**, 그래프 DB는 수치 조건 도달 시 PostgreSQL AGE 우선 |
| **GraphQL**(조회 문법) | **미채택** | 관계 탐색은 서버가 증거 가중·권한·홉 제한을 판단해야 한다. REST 3개로 끝난다. 재검토: 외부 소비자 + 엔드포인트 10개 초과 시 |

**핵심 3가지** (상세는 20번 문서):

1. **증거 등급 서열** `E0 부정(사람) > E1 사실(기계기록) > E2 정의(사람승인) > E3 추론(Jaccard)`
   — DDS §8.3 "추론이 정의를 이기지 않는다"의 일반화. 출처가 다른 확신도는 숫자로 비교할 수 없다.
2. **사용 이력이 가장 강한 관계 신호다** — Jaccard 값겹침은 코드 체계가 다른 업무 연결을 원리적으로
   못 잡는다. "같은 작업에서 함께 쓰였다"(`case_usage`)는 **비용 0으로 쌓이고**, 값이 안 겹쳐도 성립한다.
3. **관계도 측정 대상이다** — 틀린 관계는 에러 없이 조인 결과를 오염시킨다. `link_precision`으로
   재고, 임계를 손으로 정하지 않고 측정에 반응시킨다(§7과 같은 원리).

**데이터셋 역할축**: 분야 안에서 각 표가 맡는 역할(`master`·`code`·`transaction`·`plan`·`snapshot`·`bridge`)은
[`21_데이터셋_역할축.md`](21_데이터셋_역할축.md)에서 정의한다. 태그가 아니라 **동작을 바꾼다** —
조인 방향·집계 대상·기본 참조 제안·변경 감시. 특히 사용 이력이 없는 초기에도 "이 분야의 기준정보·코드표"를 제안할 수 있어 **콜드 스타트를 메운다.**

**단계**: G1(`case_usage` 기록, **1인일 — 가장 먼저**) → G2(이웃·근거 탐색) → G3(Jaccard + 가지치기
4종) → G4(작업 기반 추천) → G5(부정 엣지 + 측정). **G1이 최우선인 이유: 사용 이력은 지금부터
안 쌓으면 과거를 복원할 수 없다.**

## 12. 하지 않는 것 (경계)
