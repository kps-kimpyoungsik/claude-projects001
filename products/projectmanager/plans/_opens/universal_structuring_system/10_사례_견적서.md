# 00. 뼈대 설계서 — 견적서 자동생성 (동적 데이터셋 기반 문서 작성 시스템, QDS)

초판 2026-09-19 | 상태: **설계 초안 (구현 0)**
> **위치: 이 문서는 [`00_뼈대설계서.md`](00_뼈대설계서.md)(USS 범용 정형화 엔진)의 적용 사례 1번이다.**
> 견적서는 기준(템플릿) 1종으로 도는 인스턴스이고, 일반 원리·학습 사다리·측정 루프는 뼈대 문서에 있다.
> 여기 B1~B6은 뼈대 L1~L4의 견적서 구체화다 — B1=L1, B2=L2, B3·B4=L3, B5=승인, B6=L4.

선행: `plans/_opens/dataset_dynamic_system/` (DDS)

---

## 1. 무엇을 만드는가 — 한 문장

> 사용자가 **아무 형식의 기초 자료**를 올리면, 시스템이 그것을 **텍스트 조각 + 원본 위치**로
> 쪼개고, **처음 올린 견적서 템플릿**이 요구하는 항목에 맞춰 **정제된 데이터셋**으로 채운 뒤,
> **채우지 못한 칸만 사람에게 물어** 완성하고, **모든 값의 출처를 눈으로 확인시켜 승인**받아,
> **그 템플릿 파일 자체를 원본 서식 그대로** 채워 내보낸다.

핵심은 다섯 단어다 — **추출 · 정제 · 질의 · 승인 · 원형복원**.

## 2. 이미 있는 것 / 없는 것 (실측 2026-09-19)

새로 만들 것을 정하기 전에 **지금 무엇이 동작하는지**부터 셌다. 상상으로 설계하지 않는다.

### 2.1 이미 있다 — 그대로 쓴다

| 자산 | 실체 | QDS에서의 역할 |
|---|---|---|
| 업로드 창구 하나 | `POST /api/uploads` → `UploadService.upload()` (235줄) | **입구는 계속 하나.** 확장자 분기만 앞에 붙인다 |
| 시트 → 데이터셋 | `DatasetIngestService` (158줄) — 헤더 행 자동 탐지·중복 헤더 보정 | 표 형태 자료의 추출기 1종으로 재사용 |
| 컬럼 타입 추론 | `ColumnProfiler` — number/date/category/text | 값 검증(포맷 위반 탐지)에 재사용 |
| 스키마리스 저장 | `dataset` · `dataset_column` · `dataset_row`(payload JSON) | 정제 **전** 원자료 보관소. 건드리지 않는다 |
| **표준 뼈대** | `standard_dataset` · `standard_field` · `standard_relation` (schema.sql 293~338) | **견적서 템플릿을 여기에 등재한다** — 새 개념 0 |
| **바인딩 엔진** | `BindingEngine` (372줄) — `classify()` / `bind()` / `correct()` / `learn()` | 컬럼·라벨 → 견적서 항목 매핑을 그대로 담당 |
| **학습 루프** | `binding_feedback` (col_norm × std_field, hits/human) | 같은 표기가 반복되면 다음 견적서는 자동으로 붙는다 |
| **어휘 사전** | `vocab_term` 112건 실측 시드 + `vocab_miss` | 「인건비」=「노무비」=「M/M 비용」 동의어 해소 |
| **원천 3분류** | `Ingest.classify()` — SOURCE/DERIVED/VALUE (T115 SSI) | 항목 중복 등재 차단. 그대로 적용 |
| 근거 보존 | `dataset_binding.evidence` · `.confidence` · `.source`(rule/stat/human) | 출처 시각화의 **1차 재료** |
| POI 5.3.0 | `poi-ooxml` — xlsx뿐 아니라 **docx(XWPF)·pptx(XSLF) 포함** | 신규 의존성 없이 3종 포맷 확보 |

### 2.2 없다 — 이번에 만드는 것

| # | 결핍 | 근거(실측) | 없으면 생기는 일 |
|---|---|---|---|
| G1 | **xlsx 외 입력 0** | `UploadService`: `.xlsx` 문자열 체크만 | pdf·docx·이미지 견적 근거를 손으로 옮겨 적어야 함 |
| G2 | **셀 단위 출처 역추적 0** | `dataset_row`는 `payload` JSON + `row_no`뿐. 원본 파일의 어느 셀/문단/슬라이드였는지 잃는다 | "이 단가 어디서 나왔냐"에 답 못 함 → 승인 불가 |
| G3 | **값(value) 레벨 승인 0** | 승인은 `BindingEngine.correct()` = **컬럼↔필드 매핑**만. 개별 값에 대한 승인 상태 없음 | 매핑은 맞는데 값이 틀린 경우를 못 잡음 |
| G4 | **미충족 항목 질의 0** | `vocab_miss`는 *용어* 미탐지만 센다. "필수 항목이 비었다"는 개념 없음 | 빈칸인 채로 문서가 나감 |
| G5 | **문서 출력 0** | 출력 경로는 대시보드 렌더뿐(`DashboardService` 725줄). 파일 생성 코드 없음 | 최종 산출물이 안 나옴 |
| G6 | **템플릿 보관 0** | 업로드 원본은 `data/uploads/`에 남지만 "이게 템플릿"이라는 표식이 없다 | 원본 서식 복원 불가 |

**설계의 범위 = G1~G6 여섯 개뿐이다.** 그 밖은 전부 기존 자산 재사용이다.

## 3. 뼈대 — 6블록 파이프라인

```
 ┌─ 사용자 ────────────────────────────────────────────────────────────────┐
 │  ① 견적서 템플릿 1개 업로드   ②③④ 기초 자료 N개 업로드(형식 무관)        │
 └────────┬──────────────────────────────────────┬─────────────────────────┘
          │                                      │
   [B1 TEMPLATE]                            [B2 EXTRACT]
   템플릿 → 표준 등재                        무슨 파일이든 → 조각 + 위치
   standard_dataset/field                   source_doc / source_fragment
   quote_template(원본 파일 보관)                    │
          │                                         ▼
          │                                  [B3 REFINE]  ← 기존 BindingEngine·VocabStore
          └────────── 항목 정의 제공 ───────▶  조각 → 「항목 = 값 + 출처 + 확신도」
                                                     quote_fact
                                                          │
                              ┌───────────────────────────┤
                              ▼                           ▼
                        [B4 ASK]  미충족·저확신           [B5 REVIEW]
                        quote_gap → 질문 → 답변            출처 병렬 표시 + 승인
                              │                           quote_fact.status
                              └───────────▶ 재정제 ◀──────────┘
                                                          │ 전 필수항목 approved
                                                          ▼
                                                    [B6 RENDER]
                                          템플릿 원본 파일 + 승인값 → 최종 문서
                                          (xlsx / pptx / docx / md / txt)
```

**불변식 4개** — 이 넷이 깨지면 설계가 아니라 다른 물건이다.

| # | 불변식 | 강제 지점 |
|---|---|---|
| I1 | **출처 없는 값은 존재할 수 없다** | `quote_fact.frag_id` NOT NULL — 사람이 직접 입력한 값도 `kind=human` 조각을 만들어 붙인다 |
| I2 | **승인 안 된 값은 최종 문서에 못 들어간다** | B6 진입 게이트: 필수 항목 중 `status≠approved` 1건이라도 있으면 렌더 거부 |
| I3 | **템플릿 밖으로 나가지 않는다** | 출력은 **템플릿 원본 파일을 열어 값만 치환**한다. 새 문서를 그리지 않는다 |
| I4 | **사람 판정은 자동이 덮지 못한다** | DDS ADR 그대로 — `source=human`인 fact는 재정제 시 보존 |

## 4. 블록별 설계

### B1. TEMPLATE — 견적서 템플릿을 "표준"으로 세운다

**핵심 결정: 템플릿은 새 개념이 아니라 `standard_dataset` 1건이다.**
`STD-QUOTE`(견적서 헤더) + `STD-QUOTE-LINE`(견적 명세 1행) 두 엔티티로 잡는다.
견적서는 "머리(고객·유효기간·합계) + 반복 라인(품목·수량·단가)" 구조가 본질이기 때문이다.

```
standard_dataset  STD-QUOTE       grain="견적 1건"
standard_field    ├ customer_name  role=org   required=true
                  ├ quote_date     role=time  required=true
                  ├ valid_until    role=time
                  ├ total_amount   role=measure unit=KRW  required=true
                  └ …
standard_dataset  STD-QUOTE-LINE  grain="견적 명세 1행"
standard_field    ├ item_name      role=text   required=true
                  ├ spec           role=text
                  ├ qty            role=measure unit=EA required=true
                  ├ unit_price     role=measure unit=KRW required=true
                  ├ amount         role=measure unit=KRW   ← 파생(qty×unit_price)
                  └ remark         role=text
standard_relation STD-QUOTE.quote_id 1:N STD-QUOTE-LINE.quote_id
```

> 위 필드 목록은 **예시가 아니라 시드 초안**이다. 실제 확정은 사용자의 **실제 견적서
> 템플릿 파일 1개를 넣고 §4.B1-2 스캐너를 돌려** 뽑는다 — 상상으로 필드를 만들지 않는다
> (DDS ADR §5 "실측 기반, 상상으로 만들지 않는다" 그대로).

**B1-1. 템플릿 보관** — 새 테이블 `quote_template`:

| 컬럼 | 뜻 |
|---|---|
| `tpl_id` | `TPL-yyyyMMdd-HHmmss` |
| `std_id` | 이 템플릿이 실체화하는 표준 (`STD-QUOTE`) |
| `format` | xlsx / pptx / docx / md / txt |
| `file_path` | **원본 파일 그대로** (`data/templates/`). 이 파일이 B6의 출력 뼈대다 |
| `sha256` | 원본 무결성 — 렌더 시점에 다시 검증한다 |
| `anchor_map` | `{"customer_name": "견적!C4", "lines": "견적!A10:F##"}` — 항목 → 원본 위치 |
| `status` | draft / approved (사람 확인 후 approved) |

**B1-2. 앵커 스캔 (템플릿 → 항목 위치 자동 추출)** — 포맷별 규칙, 전부 이미 있는 POI로 가능:

| 형식 | 앵커 판정 규칙 | 반복 영역(라인) 판정 |
|---|---|---|
| xlsx | 라벨 셀(텍스트) **오른쪽/아래**의 빈 셀 = 값 자리. `{{key}}` 표기가 있으면 그것이 우선 | 헤더 행 아래 빈 행 2줄 이상 = 반복 구간 |
| docx | 표 셀 라벨 + 인접 셀 / 본문 `{{key}}` | 표의 헤더 행 1개 + 빈 데이터 행 |
| pptx | 도형 텍스트 `{{key}}` / 표 도형 | 표 도형의 데이터 행 |
| md·txt | `{{key}}` 만 인식 (구조가 없으므로 명시 표기 강제) | `{{#lines}}…{{/lines}}` 블록 |

- 자동 스캔 결과는 **초안**이다. 화면에서 사람이 "이 칸은 고객명" 을 확인·교정하고 approved.
- 교정 결과는 `BindingEngine.learn(..., human=true)`에 그대로 흘려보낸다 →
  **두 번째 템플릿부터는 같은 라벨을 자동으로 잡는다.** (학습 루프 재사용, 신규 엔진 0)

### B2. EXTRACT — 무슨 파일이든 「조각 + 원본 위치」로

**핵심 결정: Port 1개 + Adapter N개** (T102 NTM 블록 표준). 새 포맷은 어댑터 추가만으로 끼운다.

```java
public interface SourceExtractor {            // Port — 이것만 지킨다
    boolean supports(String ext);
    List<Fragment> extract(File f, String docId);
}
public record Fragment(
    String fragId, String docId,
    String locator,     // ★ 원본 위치 — "sheet:견적!C5" / "docx:p12.r3" / "pptx:s2.sh4" / "pdf:p3@[x,y,w,h]" / "img:[x,y,w,h]"
    String kind,        // cell | text | table-cell | ocr | human
    String text,
    double confidence   // 추출 자체의 신뢰도 (OCR은 1.0 미만)
);
```

| Adapter | 구현 수단 | 신규 의존성 | 상태 |
|---|---|---|---|
| `XlsxExtractor` | 기존 `SheetTableReader`·`Cells` 재사용 | 없음 | **1순위** |
| `DocxExtractor` | POI `XWPFDocument` | **없음** (poi-ooxml에 포함) | 1순위 |
| `PptxExtractor` | POI `XMLSlideShow` | **없음** (동일) | 1순위 |
| `TextExtractor` | `Files.readString` (md·txt·csv) | 없음 | 1순위 |
| `PdfExtractor` | Apache PDFBox `PDFTextStripper` | pdfbox 1개 | 2순위 |
| `ImageExtractor` | OCR | tess4j + 학습데이터(수백MB) | **보류 — §7 참조** |

**저장 2테이블:**

```
source_doc      doc_id, case_id, file_name, format, sha256, path, page_n, extracted_at, extractor
source_fragment frag_id, doc_id, locator, kind, text, confidence, seq
```

- `source_fragment`가 **G2(출처 역추적)의 해답**이다. 이후 모든 값은 `frag_id`를 들고 다닌다.
- 표 형태 자료는 기존 `DatasetIngestService`로 `dataset_row`에도 그대로 적재한다 —
  **기존 경로를 끊지 않는다**(대시보드·데이터셋 화면이 계속 동작).
  즉 표 자료는 *두 벌*이 아니라 **한 벌 + 위치 색인**이다(`source_fragment.locator`가 `dataset_row`를 가리킴).

### B3. REFINE — 조각 → 「항목 = 값 + 출처 + 확신도」

정제의 실체는 `quote_fact` 한 테이블이다.

```
quote_fact  case_id, field_key, line_no(머리항목은 0), value, value_norm,
            frag_id(★출처), confidence, source(rule|stat|vocab|human|calc),
            status(candidate|conflict|approved|rejected), evidence, updated_at
```

**정제 4단 — 싼 것부터 (DDS ADR 6 "3계층 에스컬레이션" 그대로 재사용):**

| 단 | 방법 | 쓰는 기존 자산 | 예 |
|---|---|---|---|
| R1 | 표 헤더 → 항목 규칙 매칭 | `BindingEngine.classify(header, "STD-QUOTE-LINE")` | `단가` → `unit_price` |
| R2 | 어휘 사전 동의어 | `VocabStore` 112건 | `노무비`·`M/M 비용` → `labor_cost` |
| R3 | 라벨-값 근접 규칙 (비표 문서) | 신규(작음) — 라벨 우측/하단 토큰 | `유효기간: 2026-10-31` → `valid_until` |
| R4 | 계산 파생 | 신규(작음) | `amount = qty × unit_price`, `total = Σamount` — `source=calc` |

- **모든 fact에 `evidence` 문자열을 남긴다** — "헤더 '단가' 규칙 일치(conf 0.92)" 처럼
  **사람이 읽을 수 있는 한 줄**. `dataset_binding.evidence`와 같은 규격이다.
- **충돌**(같은 `field_key`에 서로 다른 값 2건 이상) → 지우지 않고 `status=conflict`로 **둘 다 남긴다.**
  선택은 B5에서 사람이 한다. *자동 병합 금지* (T115 SSI §4).
- **원천 3분류 적용**: `Ingest.classify()`로 SOURCE/DERIVED/VALUE를 가른다.
  `계약금액`·`계약금액(VAT포함)`은 항목 2개가 아니라 **1항목 + 파생**이다.

### B4. ASK — 정리 안 된 기준을 질의로 닫는다

**질의를 만드는 트리거 3종** (사람에게 물을 것만 물어야 한다 — 과잉 질문은 시스템을 못 쓰게 만든다):

| 트리거 | 조건 | 질문 형태 |
|---|---|---|
| Q-A 미충족 | `standard_field.required=true` 인데 fact 없음 | "견적 유효기간이 자료에 없습니다. 언제까지입니까?" (자유입력) |
| Q-B 충돌 | `status=conflict` | "단가가 두 값으로 읽힙니다. 어느 것입니까?" **+ 두 출처를 나란히 표시** (선택) |
| Q-C 저확신 | `confidence < 0.6` | "이 값을 '수량'으로 읽었습니다. 맞습니까?" (확인/교정) |

```
quote_gap  gap_id, case_id, field_key, line_no, kind(A|B|C), question,
           options(JSON — B·C일 때 후보+출처), answer, answered_by, answered_at, status
```

- 답변은 **fact를 만들거나 고친다** → `source=human`, `frag_id`는 `kind=human` 조각을 새로 만들어 붙인다(I1 유지).
- 답변은 **동시에 사전·학습에 먹인다** — `VocabStore`에 동의어 추가 / `BindingEngine.learn(human=true)`.
  **같은 질문을 두 번 하지 않는 것**이 이 블록의 존재 이유다.
- 질의는 **한꺼번에 모아 1회 제시**한다(필드 하나마다 대화 왕복 금지).

### B5. REVIEW — 출처 기반 시각화와 승인

화면 1개. **왼쪽 = 템플릿 모양 그대로의 폼, 오른쪽 = 원본 미리보기.**

```
┌──────────────────────────────┬───────────────────────────────┐
│  견적서 (템플릿 레이아웃)     │  원본 근거                     │
│  고객명  [(주)중소기업중앙회]🟢│  견적요청서.pdf  p.1          │
│  유효기간[2026-10-31]      🟡 │  ┌──────────────────────┐    │
│  ─ 명세 ─                     │  │ …수신: (주)중소기업…  │◀── │
│  1 WEB개발 12M/M 8,000,000 🟢 │  └──────────────────────┘    │
│  2 인프라   1식 3,000,000  🔴 │  하이라이트 = 이 값이 나온 자리│
│  합계          11,000,000 🟢⚙ │                               │
└──────────────────────────────┴───────────────────────────────┘
🟢 승인됨(출처 확인)  🟡 추론(확신도 표시·승인 대기)  🔴 미충족/충돌  ⚙ 계산값
```

- **값을 클릭 → 오른쪽이 그 `frag_id`의 원본으로 점프 + 해당 구간 하이라이트.**
  `locator`가 이걸 가능하게 하는 유일한 장치다(그래서 B2에서 필수로 잡았다).
- 계산값(⚙)은 출처가 파일이 아니라 **수식**이다 — `evidence`에 `qty × unit_price` 를 그대로 보여준다.
- 승인 단위는 **항목 1건**. 일괄 승인 버튼은 두되 **🔴이 있으면 비활성**.
- 승인 로그: `quote_fact.status=approved` + 누가·언제(감사 이력). 승인 후 자동 재정제가 덮지 않는다(I4).

**신뢰 표시는 장식이 아니라 게이트다** — 전 필수항목 🟢 이전에는 B6 버튼 자체가 눌리지 않는다(I2).

### B6. RENDER — 템플릿 원본 그대로, 값만 채운다

**핵심 결정: 문서를 "그리지" 않는다. 템플릿 파일을 열어 앵커 위치의 값만 치환하고 저장한다.**
이래야 서식·로고·인쇄영역·수식·브랜딩이 한 톨도 안 바뀐다 — README의
"화면을 다시 쓰면 반드시 원본과 미세하게 어긋난다" 와 같은 원칙이다.

| 형식 | 방법 | 반복 라인 처리 |
|---|---|---|
| xlsx | POI `Workbook` open → `anchor_map` 셀에 `setCellValue` | 템플릿 행을 `shiftRows`로 복제 후 채움(스타일 유지) |
| docx | `XWPFDocument` → 런(run) 텍스트 치환 | 표 행 복제(`CTRow` copy) |
| pptx | `XMLSlideShow` → 도형·표 텍스트 치환 | 표 행 복제 |
| md·txt | 문자열 치환 + `{{#lines}}` 블록 반복 | 라인 블록 반복 출력 |

```
quote_render  render_id, case_id, tpl_id, format, out_path, sha256,
              rendered_at, rendered_by, fact_snapshot(JSON — 이때 쓴 값 전량)
```

- `fact_snapshot`이 **"이 문서는 이 값들로 만들어졌다"** 를 영구 고정한다. 나중에 값이 바뀌어도
  **발행된 문서의 근거는 변하지 않는다**(재현 가능).
- 렌더 직전 `quote_template.sha256` 재검증 — 템플릿이 바뀌었으면 **중단하고 알린다**(조용히 다른 서식으로 내보내지 않는다).
- **`{{key}}` 미치환 잔재가 1개라도 남으면 저장하지 않는다** — 빈칸 문서가 나가는 것이 최악이다.

## 7. 단계 계획 — **별도 계획을 두지 않는다** (정정 2026-09-19)

> **초판의 Q0~Q8 단계표는 삭제했다.** 뼈대([`00_뼈대설계서.md`](00_뼈대설계서.md) §10)의
> U0~U10과 **거의 같은 작업을 두 벌로 세고 있었다** — 두 문서를 각각 읽은 사람이 47인일로
> 오해하거나, 한쪽만 갱신돼 갈라진다(T39 CRZ 중복 정본).

견적서 인스턴스는 뼈대 단계에 **그대로 올라탄다.** 대응만 적는다:

| 이 문서 | 뼈대 Phase | 비고 |
|---|---|---|
| B2 추출 | U1 | 동일 |
| B1 템플릿·앵커 | U2 | `TemplateAdapter` 가 곧 B1-2 앵커 스캔 |
| B3 정제 | U3 | 동일 |
| B5 검토·승인 | U4 | 동일 |
| B4 질의 | U6 | 동일 |
| B6 렌더 | U7 | 견적서가 U7의 **첫 투영 대상** |

**견적서 고유 작업은 하나뿐이다** — `STD-QUOTE`/`STD-QUOTE-LINE` 표준 시드(U2 내, 0.5인일).
나머지는 전부 뼈대 기능이다. 별도 인일을 더하지 않는다.

### 보류하는 것과 이유

| 항목 | 판단 | 이유 |
|---|---|---|
| **이미지 OCR** | **보류** | tess4j + 한국어 학습데이터(수백MB) + 정확도 튜닝이 Q1~Q6 전체와 맞먹는다. 이미지는 **"조각 0건 + 사람이 보고 입력"** 경로(Q-A 질의)로 먼저 수용하고, 실제로 이미지 자료 비중이 확인되면 그때 붙인다 |
| **LLM 추출** | **기본 OFF** | DDS ADR 6 그대로 — 규칙·통계가 못 잡은 것만, 옵션으로. 근거 없는 값 생성이 I1을 정면으로 깬다 |
| 템플릿 재디자인·서식 편집 | **범위 밖** | 우리는 템플릿을 **채우는** 시스템이다. 만드는 시스템이 아니다 |
| 견적 승인 결재선·전자서명 | 범위 밖 | 요구되면 별도 |

## 8. 설계 결정 (ADR)

| # | 결정 | 대안 | 왜 이쪽인가 |
|---|---|---|---|
| Q-A1 | 템플릿 = `standard_dataset` 1건 | 견적서 전용 스키마 신설 | 표준·바인딩·학습·승인 4개 엔진이 **이미 그 모델 위에 있다**. 신설하면 4개를 다시 만든다 |
| Q-A2 | 출처는 `locator` **문자열** 1개 | 포맷별 위치 테이블 분리 | 포맷마다 좌표계가 달라 정규화가 불가능하다. 문자열 + 포맷 prefix가 확장에 열려 있다(T102 Port) |
| Q-A3 | 렌더 = 템플릿 파일 **치환** | 템플릿 파싱 후 재생성 | 재생성은 반드시 원본과 어긋난다(README 화면 이관에서 이미 겪음). 치환은 서식을 건드릴 수 없다 |
| Q-A4 | 충돌은 **둘 다 남기고** 사람이 고름 | 확신도 높은 쪽 자동 채택 | 자동 병합 금지(T115 SSI). 견적 금액을 시스템이 임의 선택하면 사고다 |
| Q-A5 | 표 자료는 `dataset_row`에도 계속 적재 | `source_fragment`로 일원화 | 기존 데이터셋·대시보드 경로를 끊지 않는다. 회귀 위험 0 |
| Q-A6 | 사람 답변은 fact + **사전·학습에 동시 반영** | fact만 기록 | 같은 질문 반복이 이 시스템을 못 쓰게 만드는 1번 원인 |
| Q-A7 | OCR 보류, 이미지는 질의 경로로 수용 | Q1에 OCR 포함 | 정확도 낮은 OCR 값은 I1(출처)을 만족해도 **틀린 근거**를 만든다. 없는 게 낫다 |
