# 데이터셋 동적 생성·관리 시스템 (DDS) — 설계 문서 묶음

초판 2026-09-13 | **v2 보강 2026-09-14** | 상태: **Phase 1·2 구현 완료**, Phase 0 는 2/3(인증 미결정)

## 무엇을 하려는 것인가

`데이터 > 데이터셋` 메뉴는 지금 **엑셀 시트 1개 = 데이터셋 1개**로만 동작한다.
표를 저장하고 차트로 그리는 것까지는 되지만 — 이 표가 **무엇에 관한 것인지**, **원래 어떤
모양이어야 하는지**, **용어가 무슨 뜻인지**, **애초에 데이터셋일 가치가 있는지**를 시스템이 모른다.

DDS는 네 가지를 세운다:

1. **어휘 사전** — 도메인 전문 용어의 뜻·의도·출처를 보존 흡수하고, 쓰면서 진화한다
2. **표준 데이터셋(뼈대)** — 들어오는 모든 표를 최대한 표준에 바인딩. 표준/도메인/사용자 3층 분리
3. **자격 게이트** — 의미·맥락 없는 가비지는 데이터셋 후보로 유지하지 않는다(격리, 삭제 아님)
4. **6축 의미 + 동적 생성** — 분야·영역·의미·맥락·주제·관계를 필터로 쓰는 저장된 질의 발행

## 읽는 순서

처음이면 **README → 04(뼈대) → 05(사전) → 06(게이트) → 01(6축) → 02(계획) → 03(기능)**.
04·05·06이 v2의 핵심이고, 01·03은 그 위에 얹힌 층이다.

## 핵심 결정 7가지

1. **기존 코드를 바꾸지 않는다** — `dataset` 3형제와 업로드·대시보드 경로는 그대로.
   추가되는 것은 새 테이블 12개와 `dataset` 컬럼 3개뿐. 회귀 위험 0, 중단해도 시스템은 동작.
2. **뼈대가 먼저다** — 표준 데이터셋에 바인딩되면 컬럼명이 `담당자`든 `PM`이든 질의가 하나로 통한다.
   바인딩 안 된 부분은 버리지 않고 확장 영역에 둔다.
3. **사전이 세 곳을 동시에 먹인다** — 한 번의 용어 조회가 6축 role·표준 바인딩·질의 어휘를
   한꺼번에 해결한다. 그래서 사전은 부속이 아니라 중심이다.
4. **가비지는 거르되 지우지 않는다** — 8지표 100점 중 40점 미만은 격리. 오판정은 반드시 생기고,
   사전이 자라면 어제의 쓰레기가 오늘의 데이터가 되기 때문이다.
5. **주/부를 가린다** — 같은 표준에 바인딩된 표 중 정본 하나만 기본 질의에 참여한다.
   안 그러면 같은 화면을 세 번 센다.
6. **싼 것부터 (3계층)** — 규칙 → 통계/임베딩 → LLM. LLM은 기본 OFF이고 앞 단계 미달분만.
   모든 판정에 `confidence`와 `source`(rule/stat/embed/llm/human). **human은 덮이지 않는다.**
7. **표준은 승인 없이 못 바꾼다** — 자동 평가 5기준(80점) + 사람 승인 2단.
   MAJOR 변경은 영향도 리포트 없이 발행 불가. "몇 개가 깨지는지 모르는 채 바꾸지 않는다."
