# 02. 구현 계획서 — DDS (Dynamic Dataset System) **v2 세분화판**

> v1(2026-09-13)은 Phase 0~4, 태스크 20개였다. v2는 **어휘 사전·표준 뼈대·자격 게이트·주/부 관계·
> 표준 승인**이 추가되면서 **Phase 0~7, 태스크 52개**로 세분화됐다.
>
> 전제는 그대로다: **기존 코드 회귀 0**, 각 Phase는 그 자체로 배포 가능, 중단해도 시스템은 동작.

---

## 0. 전체 로드맵 한눈에

```
 P0 ─ 사전정리(성능·인증)                    [2/3 완료]
   │
 P1 ─ 어휘 사전            ← 모든 것의 재료.    사전 없이는 분류도 바인딩도 못 한다
   │        (05 문서)
 P2 ─ 표준 데이터셋 뼈대    ← 사전을 써서 정의.  "원래 어떤 모양이어야 하나"
   │        (04 문서)
 P3 ─ 바인딩 + 6축 분류     ← 사전·표준을 실제 데이터에 적용
   │        (01·04 문서)
 P4 ─ CQG 자격 게이트       ← 쓰레기 컷오프. 관계·주제보다 반드시 앞
   │        (06 §2)
 P5 ─ PSR 주/부 + 관계·주제 ← 정본 판정 후 관계 추론
   │        (06 §3, 01 문서)
 P6 ─ 동적 생성·발행        ← 핵심 가치. 뷰 = 저장된 질의
   │        (03 문서)
 P7 ─ 표준 승인 관리        ← 뼈대가 자라는 문. 실사용 뒤에 온다
            (06 §4)
 P8 ─ 확장(조건부)          ← 착수 조건 충족 시에만
```

**왜 이 순서인가** — 의존이 단방향이다:
- 사전 없이 분류기를 만들면 하드코딩 사전이 코드에 박힌다(나중에 못 뺀다)
- 표준 없이 CQG를 만들면 "의도" 지표를 못 잰다(표준 바인딩이 8번 지표의 재료)
- CQG 없이 관계·주제를 돌리면 쓰레기에 가장 비싼 계산을 쓴다
- 주/부 판정 없이 뷰를 만들면 중복 집계가 기본값이 된다

## Phase 1 — 어휘 사전 (10태스크, 7인일) 【기반】

> 목표: **컬럼명 `PM` 을 넣으면 `담당자` 를 돌려주는 사전이 선다.**

| # | 태스크 | 주요 내용 | 검증 |
|---|---|---|---|
| 1-1 | 스키마 3표 | `vocab_term` · `vocab_source` · `vocab_history` (05 §4) | 기동 후 기존 화면 정상 |
| 1-2 | 흡수 경계 규칙 구현 | IN 5종 / OUT 6종 판정기 (05 §3.2). **개인정보 값 차단이 최우선** | 이름 컬럼 값이 사전에 안 들어가는지 테스트 |
| 1-3 | DB 실측 흡수기 | `ia_screen.d1/d2`·`defect.status`·`wbs_task.big` DISTINCT → 개념어·코드값 초안 | 시드 ≥ 50건, 개인정보 0건 |
| 1-4 | 컬럼명 흡수기 | 3테이블 컬럼명 63개 → 정규화·중복제거 → 속성어 초안 | 속성어 ≥ 40건 |
| 1-5 | 코드집합 추출 | distinct ≤ 20 컬럼의 값 목록 → `code_values` JSON | 5집합 이상 |
| 1-6 | 형식 규칙 | `DF-YYYY-NNN` 등 식별자 패턴 4종 | 정규식 매칭 테스트 |
| 1-7 | 매칭 엔진 | 정확→동의어→정규화 3단 조회 (05 §6). `usage_count`/`miss_count` 기록 | `PM`→`담당자` 매칭 성공 |
| 1-8 | 진화 신호 수집 | 미매칭 토큰 누적, 3회 이상 시 LOCAL draft 자동 생성 | 미지 토큰 3회 투입 → draft 생성 |
| 1-9 | 사전 API | `GET/POST/PUT /api/dds/vocab`, 이력 조회 | 응답 스키마 |
| 1-10 | 사전 화면 | 용어 트리 + 편집 + 미매칭 토큰 목록 | 등록·수정 동작 |

**DoD**: 기존 3테이블 컬럼명의 **80% 이상**이 사전으로 해석된다. `definition`·`intent` 는
초안(자동 생성 문구) 상태여도 무방 — 사람이 채우는 것은 P7에서 지속적으로.

**리스크**: 1-2 흡수 경계가 느슨하면 사전이 개인정보 저장소가 된다. **여기가 이 Phase의 SAFETY 지점.**

## Phase 2 — 표준 데이터셋 뼈대 (8태스크, 6인일) 【뼈대】

> 목표: **STD-TASK·STD-SCREEN·STD-DEFECT·STD-PERSON·STD-ISSUE 5종이 정의된다.**

| # | 태스크 | 주요 내용 | 검증 |
|---|---|---|---|
| 2-1 | 스키마 3표 | `standard_dataset` · `standard_field` · `standard_relation` (04 §3) | 기동 정상 |
| 2-2 | 3층 컬럼 추가 | `dataset` 에 `std_id`·`bind_ratio`·`level` 3컬럼 (`IF NOT EXISTS`) | 기존 데이터 무손상 |
| 2-3 | 초기 표준 5종 시드 | `wbs_task`·`ia_screen`·`defect` + 투입인력·이슈에서 필드 정의 도출 | 5종 × 필드 ≥ 8개 |
| 2-4 | required·unit·code_set 지정 | 각 표준의 필수 필드와 단위·코드집합을 사전과 연결 | required 필드가 실데이터에 실제 존재 |
| 2-5 | 표준 관계 4건 시드 | 코드에 암묵적으로 있던 관계(`defect.req_id`→`ia.screen_id` 등)를 데이터로 | 4건 등재 |
| 2-6 | 버전 규칙 구현 | MAJOR/MINOR/PATCH 판정 + 구버전 보존 | 필드 추가 시 MINOR 판정 |
| 2-7 | 표준 API | `GET /api/dds/standards`, 필드·관계 조회 | 응답 스키마 |
| 2-8 | 표준 화면 | 표준 목록 + 필드 정의 + 관계 지도 | 열람 동작 |

**DoD**: 5종 표준이 승인 상태로 존재하고, 각 필드가 사전 용어와 연결돼 있다.

**주의**: 초기 5종은 **부트스트랩 시드**라 SAG(P7) 승인 절차를 거치지 않는다. P7 가동 이후
추가·변경분부터 승인 대상이다. 이 예외를 문서에 명시해 둔다(나중에 "왜 얘들은 승인 이력이 없지?").

## Phase 3 — 바인딩 + 6축 분류 (9태스크, 7인일)

> 목표: **업로드하면 "STD-DEFECT 에 84% 바인딩, 결함 분야, 여신 영역" 이 자동으로 붙는다.**

| # | 태스크 | 주요 내용 | 검증 |
|---|---|---|---|
| 3-1 | 스키마 2표 | `dataset_facet` · `dataset_binding` (01 §4.1, 04 §4) | 기동 정상 |
| 3-2 | 바인딩 엔진 | 헤더 → 사전 → 표준 필드 매핑, `bind_ratio` 산출 (04 §2.2) | 결함 시트 → STD-DEFECT ≥ 0.7 |
| 3-3 | 3층 판정 | 매핑률 구간별 STD/DOM/USR 배정 | 구간 경계값 테스트 |
| 3-4 | 규칙 분류기(T1) | 컬럼명 시그니처 → 분야. **사전 기반**(하드코딩 금지) | 미분류율 ≤ 30% |
| 3-5 | 영역 분류 | 값 도메인 매칭 → area | IA d1 값으로 영역 판정 |
| 3-6 | 컬럼 role 프로파일러 | 물리 타입 위에 업무 의미 8종 | id/time/status/measure 각 1건 |
| 3-7 | 맥락 추출기 | `upload_batch` + 최대 날짜 → context | 업로드 1건 → context ≥ 2 |
| 3-8 | 인제스트 훅 | 적재 말미 호출. **실패해도 적재는 성공**(try/catch 분리) | 예외 주입 시에도 업로드 200 |
| 3-9 | 패싯·바인딩 API + 화면 | 조회·수동수정, 목록 배지·필터 | 확신도 0.7 미만 흐리게 표시 |

**DoD**: 기존 데이터셋 전건에 분야·맥락이 붙고, 표준 매핑률이 보인다.

## Phase 4 — CQG 자격 게이트 (7태스크, 5인일) 【가비지 컷오프】

> 목표: **표지·범례·빈 양식이 데이터셋 목록에서 사라진다(삭제는 안 하고 격리).**

| # | 태스크 | 주요 내용 | 검증 |
|---|---|---|---|
| 4-1 | 스키마 1표 | `dataset_qualification` (06 §2.3) | 기동 정상 |
| 4-2 | 규모 하한 | 행 ≥ 3, 유효컬럼 ≥ 2 미만은 즉시 REJECTED(점수 계산 생략) | 2행 표 → REJECTED |
| 4-3 | 8지표 계산기 | 15/10/15/10/15/10/10/15 배점 (06 §2.1). **전부 기존 프로파일 재사용** | 데이터셋 1개 ≤ 1초 |
| 4-4 | 3구간 판정 + 격리 | 70/40 컷오프, REJECTED는 숨김(삭제 금지) | 격리 후 원본 행 무손상 |
| 4-5 | 파이프라인 배치 | **관계·주제보다 앞**에 배치, REJECTED 조기 종료 | REJECTED 건에 군집 미실행 확인 |
| 4-6 | override + 재평가 | 사람 판단 고정, 사전·표준 갱신 후 재평가 배치 | override 건이 재평가에 안 덮임 |
| 4-7 | API + 화면 | 점수 내역(8요소) 노출, 격리 목록 화면 | 왜 떨어졌는지 사람이 읽을 수 있는가 |

**DoD**: 실제 업로드 파일 1개(시트 여러 개)를 넣었을 때 표지·범례가 격리되고 실데이터만 남는다.

**검증 포인트**: `backend/data/uploads/` 의 기존 20여 개 xlsx 로 전수 평가 → 격리율과 오판정을
육안 확인. **오판정 1건이라도 있으면 배점 재조정 후 재실행**(06 Q2).

## Phase 5 — 주/부 관계 + 관계·주제 (8태스크, 7인일)

> 목표: **같은 IA 화면목록 3개 중 무엇이 정본인지 판정되고, 중복 집계가 사라진다.**

| # | 태스크 | 주요 내용 | 검증 |
|---|---|---|---|
| 5-1 | 스키마 1표 | `dataset_canon` (06 §3.2) | 기동 정상 |
| 5-2 | 순위 점수기 | CQG30 + 바인딩25 + 커버리지20 + 신선도20 + 사람±100 | 252행 본이 41행 발췌본을 이김 |
| 5-3 | 부 관계 4종 판정 | subset / older_version / derived / variant | 부분집합 판정 정확 |
| 5-4 | 질의 기본 필터 | primary + variant 기본, `scope=all` 확장 | 중복 집계 사라짐 |
| 5-5 | 관계 추론(T2) | Jaccard. **`standard_relation` 이 있으면 그것 우선** | IA↔결함 링크 자동 생성 |
| 5-6 | 추론 성능 가드 | 값 2,000 샘플링, 데이터셋 30개 초과 시 배치 분할 | 30개 기준 ≤ 30초 |
| 5-7 | 주제 군집(T2) | 텍스트 값 → 임베딩 → 군집 → 대표어. **임베딩은 교체 가능 인터페이스** | 결함내용 151건 → 군집 ≥ 3 |
| 5-8 | LLM 어댑터(T3, 기본 OFF) | 스키마 강제 + 실패 1회 재시도 + 미분류 폴백 | OFF 상태 전 기능 정상 |

**DoD**: 주/부가 판정되고, IA↔결함 관계가 자동으로 잡히며, 결함내용이 주제별로 묶인다.

**리스크**: 5-7 임베딩 조달 미정. **1차는 c-TF-IDF(의존성 0)로 인터페이스만 확정**하고 넘어간다.

## Phase 7 — 표준 승인 관리 (6태스크, 5인일)

> 목표: **뼈대가 자라는 문이 열린다 — 아무나 못 올리고, 아무도 못 올리지도 않게.**

| # | 태스크 | 주요 내용 | 검증 |
|---|---|---|---|
| 7-1 | 스키마 1표 | `std_proposal` (06 §4.3) | 기동 정상 |
| 7-2 | 자동 평가 5기준 | 재사용25 + 안정20 + 완결20 + 무충돌20 + 호환15, 통과선 80 | 중복 표준 제안 → 자동 반려 |
| 7-3 | 중복 → 확장 전환 | 기존 표준과 겹침 ≥ 0.6 이면 "신설 대신 확장" 제안 | 유사 표준 투입 시 전환 제안 |
| 7-4 | 영향도 리포트 | MAJOR 시 영향 데이터셋 전수 + 바인딩 변화 + 롤백 절차 | 리포트 없이 MAJOR 승인 불가 |
| 7-5 | 승인 워크플로 | propose → evaluate → review → publish. 사유 필수 | 사유 없으면 저장 거부 |
| 7-6 | 승격 제안 자동화 | 어휘 `usage_count`·도메인 반복 사용 → 자동 제안(등재 아님) | 제안 생성, 자동 승격 안 됨 |

**DoD**: 표준 제안 1건이 자동평가 → 사람 승인 → 발행까지 완주한다.

## 10. 테스트 계획 (프레임워크 추가 없음 — 기존 JUnit)

현행 4개(`WbsRead`·`DbSource`·`DashboardAggregate`·`DatasetWriterQuery`) 옆에 9개를 더한다.

| 테스트 | Phase | 통과 조건 |
|---|---|---|
| `VocabBoundaryTest` | P1 | **개인정보 값이 사전에 안 들어간다**(OUT 경계) — 최우선 |
| `VocabMatchTest` | P1 | `PM`→`담당자` 동의어 매칭, miss_count 증가 |

| `FacetClassifyTest` | P3 | 결함 헤더 → domain=결함, confidence ≥ 0.8 |
| `ColumnRoleTest` | P3 | role 8종 중 4종 정확 판정 |
| `QualificationTest` | P4 | 표지 시트 REJECTED, 실데이터 QUALIFIED, **원본 무손상** |

| `LinkDiscoveryTest` | P5 | IA↔결함 링크, 표준 관계가 추론보다 우선 |

**회귀 방어**: 기존 4개 17건이 매 Phase 끝에서 그대로 통과해야 한다.

## 11. 롤백 계획

| 상황 | 조치 |
|---|---|
| 사전이 오염(개인정보 유입) | 해당 `vocab_source` 의 term 전량 삭제 + `scope_in` 재정의. 이력이 남아 범위 특정 가능 |
| 분류기 오분류 대량 | `DELETE FROM dataset_facet WHERE source <> 'human'` + 재분류. 원본 무손상 |
| CQG 오판정 대량 | 컷오프 임계 조정 후 재평가. 격리물은 삭제 안 했으므로 전량 복구 가능 |
| 주/부 판정 오류 | `dataset_canon` 재계산. 사람 지정(`pinned_by`)은 보존 |
| 표준 MAJOR 사고 | 구버전 `standard_field` 보존돼 있으므로 구버전 바인딩 복원 |
| 전면 롤백 | 추가 테이블 DROP + `dataset` 추가 컬럼 3개 제거 + 훅 제거. 기존 테이블 원상 |
