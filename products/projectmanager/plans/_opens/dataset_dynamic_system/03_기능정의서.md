# 03. 기능 정의서 — DDS (Dynamic Dataset System)

API prefix 는 기존 규칙(`API prefix = 도메인`)을 따라 **`/api/dds/**`** 로 고정한다.
기존 `/api/datasets/**`(적재된 표 자체)와 역할이 다르다 — `dds` 는 **의미와 질의**를 다룬다.

## 2. API 정의

### 2.1 패싯 (F-10 ~ F-15)

| 메서드 | 경로 | 설명 | 응답 |
|---|---|---|---|
| GET | `/api/dds/facets` | 축별 값 목록 + 각 값의 데이터셋 수 | `[{axis, value, count, parent}]` |
| GET | `/api/dds/facets?axis=domain` | 특정 축만 | 동일 |
| GET | `/api/dds/datasets/{id}/facets` | 데이터셋 1개의 전 패싯 | `[{axis, value, target_type, col_name, confidence, source, evidence}]` |
| GET | `/api/dds/datasets?axis=domain&value=결함` | 패싯으로 데이터셋 검색 (AND 다중 지정 가능) | `[{dataset_id, name, row_count, facets:[...]}]` |
| POST | `/api/dds/datasets/{id}/facets` | 수동 태그 추가 (source=human 고정) | `{facet_id, ...}` |
| DELETE | `/api/dds/facets/{facetId}` | 태그 삭제 | `{ok:true}` |
| POST | `/api/dds/classify` | 분류 실행. body `{datasetIds?:[], tiers?:["T1","T2"]}` — 생략 시 전체·T1+T2 | `{classified, skipped, unknown, elapsedMs}` |

## 3. 화면 정의

### 3.1 메뉴 구조 변경 (`Shell.jsx` GROUPS)

```
데이터
 ├ 데이터셋          /data/sources        (기존 — 패싯 배지·필터 추가)
 ├ 데이터셋 만들기    /data/build          (신규, F-30~F-32)
 ├ 의미 관리         /data/semantics      (신규, F-14/F-20/F-33)
 └ 대시보드          /data/dashboards     (기존 — 변경 없음)
```

### 3.2 화면별 정의

| 화면 | 경로 | 구성 | 주요 동작 |
|---|---|---|---|
| **데이터셋 목록**(개선) | `/data/sources` | 좌: 패싯 필터(축별 체크박스) / 우: 목록. 행마다 분야·영역 배지 | 패싯 클릭 → 즉시 필터. 미분류는 "분류 필요" 배지 |
| **데이터셋 상세**(개선) | `/data/sources/{id}` | 기존 미리보기 + **의미 탭**(컬럼별 role·확신도·출처) + **연결 탭**(링크 목록 + overlap 수치) | 태그 수정(human), 링크 클릭 시 상대 이동 |
| **데이터셋 만들기**(신규) | `/data/build` | 3단 스텝: ① 조건 선택(패싯 + 필터) → ② 미리보기(200행 + 근거 패널) → ③ 저장/발행 | 미리보기 없이는 저장 버튼 비활성 |
| **의미 관리**(신규) | `/data/semantics` | 탭 3개: 어휘(트리 편집) / 분류 현황(축별 커버리지·미분류 목록) / 관계 지도(데이터셋 노드 + 링크) | 재분류 실행, 미분류 건 일괄 지정 |

### 3.3 화면 규칙

- **확신도 표기 의무**: 태그 배지에 확신도 0.7 미만이면 흐린 스타일 + 툴팁으로 근거(`evidence`) 노출.
  근거 없이 단정적으로 보여주지 않는다.
- **출처 아이콘**: rule / stat / embed / llm / human 을 구분해 표시. human은 잠금 아이콘.
- **관계 지도**: 노드 30개 초과 시 분야(domain) 단위로 접어서 표시 — 전부 그리지 않는다.

## 4. ViewSpec 스키마 (F-30 계약)

```json
{
  "facets": {                                  // 대상 데이터셋 축소 조건 (AND, 축 내부는 OR)
    "domain": ["결함"],
    "area":   ["여신", "공통"],
    "topic":  []
  },
  "sources": ["DS-20260910-101500-1"],         // 선택: 데이터셋 직접 지정 (facets 와 OR 아님 — 교집합)
  "join": { "mode": "auto", "maxHops": 2 },    // auto = dataset_link 경로 탐색 / none = 조인 안 함
  "select": [                                  // 생략 시 role 기준 기본값(id, time, status, measure)
    {"col": "결함ID"}, {"col": "등록일"}, {"col": "심각도"}
  ],
  "filter": [                                  // AND
    {"col": "등록일", "op": ">=", "v": "2026-08-01"},
    {"col": "상태",   "op": "in", "v": ["신규", "진행중"]}
  ],
  "agg": {                                     // 선택 — 있으면 집계 결과를 반환
    "groupBy": ["심각도"],
    "metrics": [{"col": "결함ID", "fn": "count", "as": "건수"}]
  },
  "sort":  [{"col": "등록일", "dir": "desc"}],
  "limit": 200
}
```

**검증 규칙 (400 반환)**
| 위반 | 메시지 |
|---|---|
| `facets` 와 `sources` 가 모두 비어 있음 | 대상이 지정되지 않았습니다 |
| `filter[].op` 가 허용 목록(`=`,`!=`,`>`,`>=`,`<`,`<=`,`in`,`contains`) 밖 | 지원하지 않는 연산자 |
| `agg.metrics[].fn` 이 `count|sum|avg|min|max` 밖 | 지원하지 않는 집계 |
| `limit` > 10000 | 상한 초과 (물질화 발행을 사용하세요) |
| 존재하지 않는 `col` | 해당 컬럼이 대상 데이터셋에 없습니다 (후보 컬럼 3개 제시) |

**보안**: `col`·`value` 는 **절대 SQL 문자열에 직접 넣지 않는다.** 컬럼은 `dataset_column` 에 실제
존재하는 이름만 화이트리스트 통과시키고, 값은 전부 바인딩 파라미터로 넘긴다.

## 5. 6축 값 사전 (초기 시드)

| 축 | 초기 값 | 출처 |
|---|---|---|
| domain | 일정관리, 개발, 테스트, 결함, 인프라, 인력, 이슈 | 현행 메뉴·시트 구조 실측 |
| area | `ia_screen.d1` DISTINCT + `wbs_task.big` DISTINCT | DB 실측값 — 수기 작성 안 함 |
| role | id, time, status, measure, person, org, text, ref | 고정 (확장 시 분류기 수정 동반) |
| context | source=excel/manual, batch=UP-*, baseDate=YYYY-MM-DD | `upload_batch` 에서 생성 |
| topic | (자동 생성) | 군집 결과 |
| link type | fk, same_entity, derived_from, time_aligned | 고정 |

`role` 과 `link type` 만 코드 고정이고 나머지는 데이터에서 나온다 — **사전을 손으로 채우지 않는 것이 원칙**이다.

## 6. 오류 응답 (기존 `ApiExceptionHandler` 확장)

| 상황 | 코드 | body |
|---|---|---|
| spec 검증 실패 | 400 | `{error:"INVALID_SPEC", field:"filter[0].op", message:"..."}` |
| 대상 데이터셋 0건 | 200 | 빈 결과 + `warnings:["조건에 맞는 데이터셋이 없습니다"]` (오류 아님) |
| 뷰 없음 | 404 | `{error:"NOT_FOUND"}` |
| 사용 중 어휘 삭제 | 409 | `{error:"IN_USE", count: 12}` |
| 분류 중 LLM 실패 | 200 | 해당 건만 `unknown` 처리 + `warnings` (전체 실패 아님) |

원칙: **부분 실패가 전체 실패가 되지 않는다.** 분류 1건 실패로 업로드나 조회가 깨지면 안 된다.

| POST | `/api/dds/vocab/absorb` | 흡수 실행. body `{sourceKind, scopeIn, scopeOut}` |
| GET | `/api/dds/vocab/unmatched` | 미매칭 토큰 목록(진화 신호) |
| POST | `/api/dds/vocab/{termId}/promote` | 승격 **제안** 생성(자동 승격 아님) |
| GET | `/api/dds/vocab/match?q=PM` | 매칭 테스트 — 어떤 용어로 해석되는지 |

**흡수 응답 예**
```json
{
  "sourceId": "VS-20260914-...", "absorbed": 52, "excluded": 118,
  "excludedReason": {"개인정보": 41, "1회성값": 62, "문장": 15},
  "terms": [{"term":"담당자","kind":"attribute","synonyms":"PM,책임자","confidence":0.9}]
}
```
**제외 건수와 사유를 반드시 돌려준다** — 무엇을 안 가져왔는지 모르면 경계가 맞는지 검증할 수 없다.

### 8.2 표준 데이터셋 (F-60 ~ F-65)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/dds/standards` | 표준 목록 (level·domain 필터) |
| GET | `/api/dds/standards/{stdId}` | 정의 + 필드 + 관계 + 바인딩된 데이터셋 수 |
| POST | `/api/dds/standards` | 신규 정의 → **P7 가동 후에는 `std_proposal` 경유**(직접 생성 차단) |
| PUT | `/api/dds/standards/{stdId}/fields` | 필드 추가·수정 → 버전 판정 자동 |
| POST | `/api/dds/standards/relations` | 표준 관계 추가 |
| POST | `/api/dds/bind` | 바인딩 실행. body `{datasetIds?}` |
| GET | `/api/dds/datasets/{id}/binding` | 컬럼별 바인딩 + 확신도 + 근거 |
| PUT | `/api/dds/datasets/{id}/binding` | 수동 바인딩 수정 (source=human) |

**바인딩 응답 예**
```json
{
  "datasetId": "DS-...", "stdId": "STD-DEFECT", "bindRatio": 0.84, "level": "USR",
  "bound": [{"col":"결함ID","field":"defect_id","confidence":1.0,"source":"rule",
             "evidence":"용어 '결함ID' 정확 일치"},
            {"col":"PM","field":"owner","confidence":0.9,"source":"rule",
             "evidence":"동의어 'PM'→'담당자'→owner"}],
  "unbound": ["비고2", "임시메모"],
  "missingRequired": []
}
```
`missingRequired` 가 비어 있지 않으면 **이 표는 그 표준을 자처할 수 없다** — 경고로 표시한다.

### 8.3 자격·주/부 (F-70 ~ F-76)

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/dds/qualify` | 자격 평가 실행. body `{datasetIds?}` |
| GET | `/api/dds/datasets/{id}/qualification` | 점수 + 8요소 내역 + 사유 |
| POST | `/api/dds/qualification/{id}/override` | 사람이 판정 뒤집기 (`QUALIFIED` 고정) |
| GET | `/api/dds/quarantine` | 격리 목록 (사유·점수순) |
| POST | `/api/dds/roles/resolve` | 주/부 판정 실행 |
| GET | `/api/dds/datasets/{id}/role` | primary/secondary + 관계종류 + 사유 |
| PUT | `/api/dds/datasets/{id}/role` | 사람이 primary 고정 (`pinned_by`) |

**자격 응답 예**
```json
{
  "datasetId": "DS-...", "verdict": "REJECTED", "score": 22,
  "reason": "유효 컬럼 2개, 데이터 1행 — 표지 시트로 판단",
  "breakdown": {"lexical":3,"context":10,"structure":2,"topic":0,
                "role":0,"function":0,"direction":0,"intent":7},
  "quarantined": true, "recoverable": true
}
```
**`recoverable: true` 를 항상 명시한다** — 사용자가 "지워졌나?"를 걱정하지 않게.

### 8.4 표준 승인 (F-80 ~ F-82)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/dds/proposals?status=review` | 승인 대기열 |
| POST | `/api/dds/proposals` | 제안 등록 → 자동 평가 즉시 실행 |
| GET | `/api/dds/proposals/{id}` | 제안 + 5기준 점수 + **영향도 리포트** |
| POST | `/api/dds/proposals/{id}/decide` | `{decision: approve\|revise\|reject, reason}` — **reason 필수** |
| POST | `/api/dds/proposals/{id}/publish` | 발행. MINOR는 자동 재바인딩, MAJOR는 예약 |

**자동 평가 반려 응답 예**
```json
{
  "propId": "SP-...", "autoScore": 62, "status": "rejected",
  "detail": {"재사용성":10,"안정성":12,"의미완결성":20,"충돌없음":5,"하위호환":15},
  "reason": "기존 STD-SCREEN 과 필드 겹침 0.73 — 신설 대신 확장을 제안합니다",

```

## 9. 화면 정의 (추가·변경)

```
데이터
 ├ 데이터셋            /data/sources     (배지에 표준·자격·주부 추가)
 ├ 데이터셋 만들기      /data/build       (P6)
 ├ 의미 관리           /data/semantics   (패싯·관계·주제)
 ├ 어휘 사전           /data/vocab       (신규 — P1)
 ├ 표준 데이터셋        /data/standards   (신규 — P2)
 ├ 격리 목록           /data/quarantine  (신규 — P4)
 ├ 표준 승인           /data/approvals   (신규 — P7)
 └ 대시보드            /data/dashboards  (변경 없음)
```

| 화면 | 구성 | 핵심 규칙 |
|---|---|---|
| **어휘 사전** | 계층 트리(STD/DOM/LOCAL) + 용어 편집 + **미매칭 토큰 탭** | `definition`·`source` 없으면 저장 불가. 이력 항상 열람 가능 |
| **표준 데이터셋** | 표준 목록 + 필드 정의표 + 관계 지도 + 바인딩된 데이터셋 수 | `required` 필드는 눈에 띄게. 버전 이력 노출 |
| **격리 목록** | 점수순 + 8요소 내역 + 사유 + **복구 버튼** | "삭제되지 않았습니다" 문구 상시 표시 |
| **표준 승인** | 대기열 + 5기준 점수 + 영향도 리포트 | MAJOR는 영향 데이터셋 목록을 **펼친 상태**로 보여준다 |
| 데이터셋 목록(변경) | 배지에 `STD-DEFECT 84%` · `주`/`부(subset)` · `보완필요` 추가 | 부·보완필요는 기본 접힘, 토글로 표시 |

## 10. 오류 응답 (추가)

| 상황 | 코드 | body |
|---|---|---|
| 용어 등록 시 definition/source 누락 | 400 | `{error:"VOCAB_INCOMPLETE", missing:["definition"]}` |
| 흡수 경계 위반(개인정보 감지) | 200 | 흡수는 성공, `excluded` 에 사유 기록 (오류 아님) |
| 표준 required 필드 없는 바인딩 | 200 | `missingRequired:[...]` + `warnings` |
| P7 가동 후 표준 직접 생성 시도 | 409 | `{error:"PROPOSAL_REQUIRED", proposeUrl:"/api/dds/proposals"}` |
| 승인 결정에 reason 없음 | 400 | `{error:"REASON_REQUIRED"}` |
| MAJOR 발행 시 영향도 리포트 없음 | 409 | `{error:"IMPACT_REPORT_REQUIRED"}` |
| 격리된 데이터셋을 뷰 대상으로 지정 | 200 | 결과에서 제외 + `warnings:["DS-... 는 격리 상태로 제외됨"]` |

원칙은 그대로다 — **부분 실패가 전체 실패가 되지 않고, 제외한 것은 반드시 알린다.**
