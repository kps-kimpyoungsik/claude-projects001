# 개인정보 보호 지침 — 지켜야 할 규칙

작성 2026-09-24 | 구조: [`00_설계서.md`](00_설계서.md) | 적용: projectmanager 전체 (백엔드·프론트·문서·저장소)

근거: 개인정보 보호법 §3(처리 원칙)·§28-2(가명처리)·§28-4(추가정보 분리)·§29(안전조치 의무),
「개인정보의 안전성 확보조치 기준」 암호화 조항(고유식별정보·비밀번호·바이오정보). 법 조문 해석이 필요한
판단은 이 문서가 아니라 개인정보 보호책임자가 한다.

---

## 저장

- **G-1 분류 먼저.** 새 컬럼·새 업로드 형식을 만들면 `PiiRegistry` 에 등급(P0~P3)을 먼저 적는다.
  등급 없는 개인정보 컬럼은 만들지 않는다.
- **G-2 P2 는 토큰만.** 업무 테이블·데이터셋 payload·로그에 성명·전화·이메일 원문을 쓰지 않는다.
  쓰는 길은 `PiiVault.tokenize()` 하나뿐이다.
- **G-3 P3 는 받지 않는다.** 주민번호·여권·운전면허·외국인등록번호·계좌·카드·비밀번호는 적재하지 않는
  것이 원칙이다. 업로드에서 탐지되면 그 셀은 저장하지 않고 경고한다. 업무상 불가피하면 보호책임자 승인 후
  금고 암호문으로만 두고, 토큰 검색 대상에서 뺀다. 비밀번호는 암호화가 아니라 일방향 해시다.
- **G-4 원문은 금고에만, 금고엔 암호문만.** `pii_vault.enc` 외의 어떤 컬럼에도 P2/P3 원문이 없어야 한다.

## 키

- **G-5 개인키는 저장소 밖.** `*.pem` 중 개인키는 절대 커밋하지 않는다(`.gitignore` 로 막혀 있다).
  위치는 `PM_PII_PRIVATE_KEY` 환경변수로만 알려준다. 개인키 사본은 최대 2곳(운영 서버 + 오프라인 보관)이다.
- **G-6 색인키는 비밀.** `PM_PII_INDEX_KEY` 는 `.env` 에만 둔다. 공개키처럼 배포하지 않는다.
- **G-7 유출 시 교체.** 개인키 유출 → 새 키쌍 생성, 금고 전체 재암호화, 옛 개인키 폐기.
  색인키 유출 → 새 색인키로 토큰 재계산(전환 API 재실행). 교체 이력은 `TODO.md` 에 남긴다.

## 화면·API

- **G-8 기본은 마스킹.** 응답은 기본적으로 `김*수#3fa2c1` 형태다. 원문은 `pm.pii.reveal=true` 이면서
  개인키가 로드된 서버에서만 나간다. 외부에 노출되는 서버(`vite --host`·tailnet 공개)는 `reveal=false` 다.

## 데이터 수명

- **G-9 평문 사본을 남기지 않는다.** 전환 전 DB 백업·엑셀 원본·내보내기 파일은 평문이다. 목적을 다하면
  폐기하고, 보관해야 하면 `seal` 로 봉인한 파일만 남긴다. H2 는 전환 후 `SHUTDOWN COMPACT`.
- **G-10 로그 금지.** 예외 메시지·로그에 원문 값을 넣지 않는다. 토큰이나 행 번호만 쓴다.

## 문서·저장소 (공개 저장소 전제)

- **G-11 공개 가능 여부를 먼저 판정.** 원격 저장소는 **공개**다. 커밋하는 모든 문서는 "외부인이 읽어도
  되는가"를 기준으로 쓴다. 내부 IP·접속 방법·계정명·고객사 실데이터는 공개 불가다.
- **G-12 공개 불가 문서는 봉인해서만 커밋.** `PiiCrypto seal` 로 암호화한 `*.sealed` 파일만 커밋하고,
  원문 파일은 `**/_private/` 에 둔다(git 제외). 복원은 개인키가 있는 곳에서 `unseal`.
- **G-13 커밋 전 검사.** `git add -n` 목록에 `data/`·`.env`·`*.pem`(공개키 제외)·`_private/` 가 없어야 한다.
  `.gitignore` 는 줄 끝 주석을 쓰지 않는다(KH-863).
