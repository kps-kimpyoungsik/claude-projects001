## 1. U5-min — 자동화가 오르는가, 믿을 만한가

### 1.1 설계와 다르게 한 것 하나: precision을 "사후 채점"이 아니라 "판정 직전 기록"으로 잰다

설계(§7.1)는 gold 플래그를 둔 fact를 따로 보관하고 엔진을 다시 돌려 채점하는 방식이다.
그런데 지금 자동 판정이 실제로 도는 곳은 **바인딩**뿐이고, 사람이 교정하면 그 값이 곧바로
학습(`binding_feedback.human`)에 들어간다. 사후에 엔진을 다시 돌리면 **외운 정답을 맞힌 점수**가 나온다.

→ 사람이 판정하는 **그 순간**, 덮이기 직전의 자동 판정을 `binding_label`에 함께 남긴다.
라벨이 생기기 **전**에 나온 예측이므로 누출(leakage)이 없다.
gold 플래그 방식은 `struct_fact`(U3)가 생길 때 필요해지므로 그때 붙인다.

### 1.2 확인도 라벨이다

교정만 기록하면 틀린 것만 쌓여 정확도가 0 쪽으로 치우친다.
교정 화면 셀렉트는 현재 값으로 미리 채워져 있어서 "맞다"를 표시할 수단이 없었다.
→ 자동 판정 행마다 **[맞음]** 버튼을 달았다. 같은 값으로 교정하면 `agree=TRUE`로 기록된다.
사람 판정을 사람이 다시 고친 것은 자동 판정 채점 대상이 아니다(`agree=NULL`).

### 1.3 숫자 3개 + 회귀 감지

| 지표 | 계산 | 화면 |
|---|---|---|
| coverage | 바인딩된 컬럼 / 전체 컬럼 | 표준 데이터셋 상단 띠 |
| auto_rate | 자동 판정이 그대로 서 있는 바인딩([맞음] 확인 포함) / 전체 바인딩 | 〃 |
| precision | 자동 판정이 맞은 라벨 / 채점 라벨 | 〃 (라벨 50건 미만이면 "참고치" 표시) |

- `POST /api/dds/metrics/snapshot` → `struct_metric`에 기록하고 직전 스냅샷과 비교한다.
  **양쪽 라벨이 50건 이상**이고 precision이 −5%p 이상 떨어지면 회귀로 보고, 전체와 원인 표준을 함께 지목한다.
- 표본이 적을 때의 흔들림은 회귀로 오보하지 않는다(테스트로 고정).
- ask_count(설계 §7.2의 4번째 숫자)는 질의 루프(U6)가 없어서 아직 셀 대상이 없다.
- **정정 2026-09-24**: 표준별 precision이 `human_std`로 걸러져 사실상 recall이었다 → `auto_std`로 교정.
  엔진이 다른 표준의 컬럼을 X로 잘못 묶어도 X의 수치가 안 떨어져 회귀 원인 표준을 놓쳤다(재현 테스트
  `엉뚱한_표준으로_잘못_묶은_회귀는_잘못_묶은_표준을_지목한다`, 수정 전 FAIL → 후 PASS, 전체 100/100).
  교정 이전에 찍힌 표준별 스냅샷과의 첫 비교 1회는 기준이 다르다(ALL은 영향 없음) — 단 운영 DB
  (`data/wbs.mv.db`)에는 `struct_metric` 테이블 자체가 아직 없어 옛 공식 스냅샷이 0건, 실제 위험 없음(실측).
- **정정 2026-09-24**: [맞음] 확인이 binding을 `source=human`으로 바꿔 검증할수록 auto_rate가 떨어졌다
  → 확인(agree=TRUE)으로 자동 판정이 그대로 선 바인딩은 자동으로 센다. 확인 후 값을 바꾸면 다시 제외(테스트 고정, 101/101).

## 2. 원본 자료 화면 (`/data/raw`, 메뉴 데이터 > 원본 자료)

- 여러 파일을 한 번에 올리되 **한 파일씩** 전송한다. 하나가 거절돼도 앞서 받은 파일은 남고, 어느 파일이 왜 거절됐는지 보인다.
- 조각 목록은 원본 위치(locator)·종류·내용을 보여준다. 이미지·음성은 "원본만 보관 — 아직 읽는 엔진이 없다"로 표시한다.
- 조각 API는 기본 500개, 최대 5,000개로 제한한다. 셀 200만 개짜리 시트를 브라우저에 통째로 보내지 않기 위해서다.
