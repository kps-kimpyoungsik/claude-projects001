# 범용 규칙 발견 엔진 + 정제 단계 — 작업 문서

착수·완료 2026-09-25 | 상태: **구현 완료 (테스트 133/133, 스모크 15/15)** · 운영 DB 재적재는 미실행(아래 5절)
요청: "특정 도메인 기반으로 구조를 분석해서 프로그램화하는 것이 아니고, 자료 기반으로 규칙을 자율적으로 찾아주는 엔진 → 자료 리스트업 → 정제 단계"

---

## 1. 원칙 — 도메인 단어 0

이전에는 역할을 컬럼명 단어(상태·일자·담당 등 목록)로 정했다. 새 자료가 오면 단어 목록을 늘려야 했다.
이제는 **값의 통계만** 본다. 테스트 컬럼명을 일부러 A·B·C로 두어 이름으로 맞히는 규칙은 통과할 수 없게 했다.
예외는 하나 — 사람 여부(person)는 개인정보 규칙(`PiiRegistry` 헤더 규칙)이라 그대로 둔다.

## 2. 구성 (`backend/.../engine/`)

| 클래스 | 하는 일 |
|---|---|
| `DataProfiler` | 컬럼 값 → 특징 17개(채움·고유·숫자·날짜·엑셀일련번호·가명토큰·길이·엔트로피·결측표기·공백·천단위·낱말수·연속정수) + 정규화 10차원 벡터 |
| `HeaderDetector` | 행마다 헤더 확률 = 0.30 문자열성 + 0.15 고유성 + 0.20 폭 + 0.35 타입대비. 대비는 빈 행에서 끊기/안 끊기 두 방식 중 큰 값. 최고점 < 0.45면 **헤더 없음**(col1…) |
| `RoleModel` | 역할 6종(id·time·measure·category·person·text). 사전 규칙(분포 임계값) → 사람 라벨 5개 이상이면 **kNN(K=3, 거리 ≤ 0.35)이 사전을 이긴다** |
| `RefinePlanner` | 값의 성질에서 정제 계획: 빈 열·결측 표기·공백·일련번호→날짜·날짜 표기 통일·숫자 서식·중복 행 (적용) / 숫자 아닌 값·IQR×3 이상치 (표시만) |
| `EngineService`/`Controller` | `GET /api/engine/inventory` · `GET /api/engine/profile/{id}` · `POST /api/engine/refine/{id}` → 원본을 두고 `{id}-R` 새 데이터셋 |

통합: `DatasetIngestService.parse`(헤더 탐지) · `FacetService`(역할) · `QualificationService`(헤더 의심 → 구조 점수 0 + "재적재 권장").
화면: 메뉴 "자료 분석"(`/data/engine`).

## 3. 실측

- **실제 엑셀 40시트** (복호화 임시본, 사용 후 삭제): 이전 방식과 같음 28 · 다름 9 · 헤더 없음 3.
  다른 9건 중 확인된 개선: 서버정보(1행), WBS_Raw(제목·메타 아래 3행), 통계(4행), 문서목록, WBS_미완료(헤더 없음).
- **운영 DB 사본 인벤토리**: 데이터셋 20 · 헤더 의심 2(WBS_미완료, 서버정보) · 정제 가능 2,082칸.
- **판정**: 정식 6 · 보완 필요 7 · 격리 7.
- **정제 시연**(진행상황 정리): 20열 → 14열, 정제본에 다시 계획을 세우면 빈 계획(멱등), 파이프라인 자동 실행.

## 4. 튜닝 이력 (전부 실측으로 발견)

| 증상 | 원인 | 조치 |
|---|---|---|
| 헤더 없는 시트에서 끝 근처 행이 헤더로 뽑힘 | 아래 데이터가 적으면 대비가 우연히 높다 | `MIN_BELOW`·`MIN_CONTRAST` |
| 작은 표(헤더+1~2행) 헤더 소실 | 고정 3행 요구 | `MIN_BELOW`를 있는 만큼으로 |
| 표가 여럿인 시트에서 아래 표 선택 | 근소한 점수 차 | `TIE` 0.05 — 위쪽 유지 |
| 빈 행으로 블록이 나뉜 표 헤더 소실 | 빈 행 경계로 1~2행만 봄 | 두 방식 대비의 최댓값 |
| 서로 다른 숫자가 id로 | 고유 = id | 연속 정수일 때만 id |
| 긴 문장이 id로 | 고유 = id | 낱말 ≤ 2 조건 |

## 5. 남은 것

- **대상목록** 2단 헤더(상위 병합 제목 + 하위 헤더) — 한 행만 고른다. 2단 병합은 미지원.
- 표지·가이드 시트는 판정이 애매하다(표가 아님). 헤더 의심/격리로 걸러지는 수준.
- **운영 DB 헤더 의심 2건 재적재** — 봉인 원본 복호화(개인키) 필요 → 사람 승인 후.
- 적재 시 자동 정제는 하지 않는다 — 정제본은 사람이 "정제본 만들기"로 만든다(원본 보존).
- 스모크: 서버 기동 직후 첫 호출이 느리면(주간 아카이브 첫 호출 수 초) 2.5초 고정 대기에서 실패한다.
